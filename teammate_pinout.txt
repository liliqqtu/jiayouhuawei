引脚核对、干簧管接线与求助键结论
交付对象：A 同学　·　依据：小熊派官方教程 + OpenHarmony device_board_bearpi 源码 + E53 接口原理图　·　2026-10-28
一、结论先行（四问四答）
1. 两块 E53 板各自用了哪些脚？　E53_IS1 = GPIO_7（人体红外输入）+ GPIO_8（蜂鸣器 PWM）；E53_IA1 = GPIO_0/GPIO_1（I²C1）+ GPIO_8（电机）+ GPIO_14（补光灯）。
2. 两块板能不能同时装？　不能。J1 只有一个 E53 座，且两块板共用 GPIO_8——这才是真正的冲突点，不是 GPIO_7。
3. 干簧管该接哪个脚？　GPIO_13（J1 第 5 脚）。绝对不要接 GPIO_7：那是人体红外的推挽输出，干簧管并在上面相当于把传感器输出短接到地。
4. 哪个板载键做求助输入？　F1 = GPIO_11（推荐）；F2 = GPIO_12 留作备用。两键都是按下接地、低电平有效，板上没有上拉电阻，必须开内部上拉。
相对你原来那张表，本次核对修正了 3 处：
① E53_IS1 除 GPIO_7 外，还占用 GPIO_8 驱动蜂鸣器（PWM1，4 kHz / 50 %）。原表漏了这一个脚，它正好和 IA1 的电机是同一个脚。
② E53_IA1 的 I²C 具体是 I²C1：SDA = GPIO_0、SCL = GPIO_1；这条总线上还并联着板载 NFC 芯片。
③ 板载按键已确认：F1 = GPIO_11、F2 = GPIO_12，低电平有效，无外部上拉（1 kΩ 串联 + 100 nF 对地）。

四、表 3  干簧管接线建议
为什么是 GPIO_13：两块 E53 板都不使用 J1 第 5 脚；这脚在板上没有接 LED、按键、NFC 或调试串口；同时它离 3.3 V（J1-13）和 GND（J1-12/14）都近，取电和接地都方便。
初始化四步（不需要写完整驱动）：
① 复用：IoSetFunc(GPIO_13, 0) 设成普通 GPIO，别留在 ADC 功能上。
② 方向：GpioSetDir(GPIO_13, IN)。
③ 上拉：IoSetPull(GPIO_13, UP)。板上没有外部上拉，不开就是悬空乱跳。
④ 中断：GpioRegisterIsrFunc(GPIO_13, EDGE, FALL, cb, NULL)，回调里做 20–50 ms 去抖 + 单次触发锁定。
上电自检三步（万用表就够）：
1）不接干簧管：J1-5 对 GND 应是 3.3 V —— 说明内部上拉生效、脚没被别的电路拉住。
2）短接 J1-5 与 GND：电压应掉到 0 V，串口能打印一次中断 —— 说明中断通路通。
3）接上干簧管：磁铁靠近 / 离开，电压在 3.3 V ↔ 0 V 之间翻转；门框长线（> 1 m）时连做 20 次，不应出现误触发。

六、共存性风险（引脚不冲突 ≠ 能一起跑）
● 机械：J1 是唯一扩展座，两块 E53 板都只能插它，物理上无法同时安装，也没有级联口。
● 电气：GPIO_8 被两块板同时占用，一块要 PWM1 波形、一块要直流高电平，同一时刻只能是一种。
● 软件：两个驱动都 init 时，后执行的 IoTGpioSetFunc 会把 GPIO_8 的复用改掉，蜂鸣器和电机必有一个失效——表现是“插着 A 板却按 B 板的逻辑动作”。
● 总线：I²C1（GPIO_0/1）上还挂着板载 NFC 芯片 NT3H1201，与 SHT30 / BH1750 共享总线和上拉；地址不冲突，但若温湿度偶发读失败，先查这里。
● 供电：J1-11 是 USB 5 V 直连，电机启动有冲击电流；后续若要双负载，建议并 100 µF 电解 + 0.1 µF 瓷片。
