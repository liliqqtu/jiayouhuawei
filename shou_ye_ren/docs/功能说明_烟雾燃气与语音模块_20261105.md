# 功能说明：烟雾 / 燃气监测与紧急求助语音播报（2026-11-05）

## 一、一句话

首页新增「安全传感」卡片，持续显示烟雾（火灾）与燃气（泄漏）两类传感器的状态；两类传感
器任一超限，走与现有一致的 L3 紧急告警链路（声光 + 通知栏 + 语音播报）。老人按下随身求助
按钮（SOS）时，语音模块播报「我需要帮助」。

## 二、需求定位（避免把加分项说成基础项）

| 能力 | 赛题口径 | 说明 |
| --- | --- | --- |
| 烟雾（火灾）监测 | 创新拓展①「多维度监测」 | 基础 5 条里没有烟雾/燃气，规则明写创新项不强制 |
| 燃气（泄漏）监测 | 创新拓展①「多维度监测」 | 同上 |
| SOS 触发语音模块播报「我需要帮助」 | 基础②「本地声光预警与自助求助（含语音模块播预设求助语音）」 | 这条本身就是基础条目的组成部分，属于把已有声光预警补上语音这一路 |

答辩时这样说不会被打断：基础五条已经闭环；烟雾/燃气是创新拓展里我们选做的「多维度监测」，
代价小、对独居老人实际意义大。

## 四、接口

### GET /api/v1/sensors

```json
{
  "deviceId": "dev-101",
  "items": [
    {"kind": "gas", "name": "燃气", "type": "GAS", "note": "燃气泄漏监测",
     "status": "normal", "statusText": "正常", "level": null, "message": null,
     "ts": null, "lastAlarmTs": null, "lastStatus": null,
     "eventId": null, "zone": null, "deviceId": "dev-101"},
    {"kind": "smoke", "name": "烟雾", "type": "SMOKE", "note": "火灾烟雾监测",
     "status": "alarm", "statusText": "报警", "level": "L3",
     "message": "烟雾报警，请立即确认", "ts": "2026-11-05T13:40:02+08:00",
     "lastAlarmTs": "2026-11-05T13:40:02+08:00", "lastStatus": "pending",
     "eventId": "evt-...", "zone": "living", "deviceId": "dev-101"}
  ],
  "alarming": 1,
  "supportedTypes": ["GAS", "SMOKE"]
}
```

同一份数据也挂在 `GET /api/v1/snapshot` 的 `sensors` 字段上，APP 首页只取快照、不多发请求。

### GET /api/v1/voice

返回是否启用与后端信息（`{"enabled": true, "backend": "tts", "port": "", "baud": 9600, ...}`）。

### POST /api/v1/voice

- `{"key": "SOS"}`：按短语表播报（SOS → 「我需要帮助」）
- `{"text": "自定义内容"}`：临时播报一句话
- 未启用语音模块时返回 400 `VOICE_DISABLED`，避免前端静默失败

## 五、语音模块对接（BY8301）

### 5.1 串口帧

```
7E FF 06 03 00 00 [曲目号] [校验和] EF      # 共 9 字节
校验和 = (0x100 - ((FF+06+03+00+00+曲目号) & 0xFF)) & 0xFF
```

### 5.2 曲目号

| 曲目 | 内容 | 触发 |
| --- | --- | --- |
| 1 | 我需要帮助 | SOS（随身按钮） |
| 2 | 检测到燃气泄漏，请立即查看 | GAS |
| 3 | 检测到烟雾，请立即查看 | SMOKE |
| 4 | 检测到紧急情况，请立即查看 | FALL / FALL_DOWN |
| 5 | 检测到火情，请立即查看 | TEMP_FIRE |

录音建议：同一个人、同一语速、安静环境录 5 条，转成模块支持的 MP3（BY8301 通常 8–48 kHz
采样），按上表顺序烧进模块内存。

### 5.3 三种后端

| 后端 | 用途 | 命令 |
| --- | --- | --- |
| `log`（默认） | 无硬件演示，只记日志 + 打印，`data/voice.log` 可查 | `--voice --voice-backend log` |
| `tts` | 用电脑音箱代播，演示效果接近 | `--voice --voice-backend tts` |
| `serial` | 真模块，走 USB 转串口 | `--voice --voice-backend serial --voice-port COM5 --voice-baud 9600` |

接线：模块 VCC/GND 接 5V/GND，TX/RX 与 USB 转串口交叉相接；模块本身的「按键触发播放」
可以先不用，由网关按告警类型选曲，接上后按说明书核对一次曲目号即可（本文档固件帧按 BY8301
通用指令写，帧生成函数 `build_by8301_frame` 独立，改一处即可）。

## 六、APP 改动

- 模型：`SafetySensor`（kind/name/type/status/statusText/lastAlarmTs/...）、`SensorStatusPayload`。
- 首页「安全传感」卡片：两个格子（烟雾/燃气），正常绿点、报警红底红框；副标题显示报警时间
  或上次报警时间，未接入显示「火灾监测未接入」「泄漏监测未接入」——不假装有传感器。
- 报警时同时走已有链路：告警页待确认列表、通知栏提醒、语音播报、声音告警。

## 七、30 秒演示脚本

1. `python run_gateway.py --voice --voice-backend tts`（或 `start_all` 里对应的启动项）
2. 首页「安全传感」两格均为「正常 · 还没有报警记录」
3. 终端：`python sim/incident.py --type smoke`
4. 期望：首页烟雾格变红「报警」、通知栏弹「守夜灯 · 紧急告警」、电脑音箱播
   「检测到烟雾，请立即查看」、告警页出现 L3 待确认
5. 告警页确认 + 处置 → 首页回到「正常」
6. `python sim/incident.py --type gas` 重复一次，观察燃气格
7. 长按首页「一键求助」1 秒 → 语音播「我需要帮助」

## 九、边界与后续（答辩要如实说）

1. 串口帧未在实物模块上跑过验证：脚本按 BY8301 通用指令写，接上后需要按说明书核对一次
   曲目号与波特率；真机演示前建议先 `--voice-backend log` 走一遍，再切 `serial`。
2. 板端直连（按钮 → 固件 → 模块，不经过网关）目前没有做：板上只有蜂鸣与 LED，语音由网关
   侧驱动；如果评委问「断网还能播吗」，如实答「语音播报走本地网关，网断了网关仍在本机，
   播报不受影响；只有跨设备推送需要网络」。
3. 烟雾/燃气是创新拓展项，不作为基础条目计分；传感器数值来自模拟器或 MQ-2/MQ-5 模块，
   阈值与报警文案走的是与温度/门磁同一套规则引擎。
4. 想再加一层：把 `smoke`/`gas` 做成服务卡片（万能卡片）常驻桌面，属于可选加分项，本轮未做。

## 十、答辩问答

**Q1：烟雾/燃气是赛题要求吗？**
A：不是。基础 5 条里没有这两项，它们是创新拓展第 1 条「多维度监测」；规则明确写了高阶能力
作为加分项、不做强制要求。我们选它是因为独居老人厨房场景真实需要，且和已有告警链路同构，
改造成本低。

**Q2：语音是电脑放的还是板子放的？**
A：演示用网关侧驱动语音模块（本机接串口或先用系统 TTS 代播），板端负责声光与按钮；这也是
硬件组原计划的 BY8301 接法。断网时网关和模块都在本地，播报不受影响。

**Q3：烟雾报警会不会误报？**
A：会，所以和温度/门磁一样走「确认 + 处置结果 + 关闭」的闭环，处置后同一设备同类型告警进入
冷却，避免连续刷屏；MQ-2 这类传感器需要预热，演示前会先跑一遍基线。

**Q4：为什么不直接买带语音的成品报警器？**
A：我们做的是「一张网」：传感器、网关、APP、家庭组、告警闭环在同一条链上，成品报警器只能
单点响，无法把「谁去看了、处理结果是什么」留痕。
