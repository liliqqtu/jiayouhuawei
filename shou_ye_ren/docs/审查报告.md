## 一、数据模型字段完整性

| 对象 | 字段 | 实现位置 | 结论 |
|---|---|---|---|
| `SensorSnapshot` | deviceId, ts, seq, pirDetected, lastMotionTs, lastMotionZone, temperature, humidity, lux, doorOpen, battery, powerState, rssi, online, source, fwVersion | 固件 `app_main.c::build_snapshot`；网关 `api.ingest_snapshot`；APP `Models.ets` | ✅ 16 字段全 |

**null 约束**：`Env_ReadTempHum/Env_ReadLux` 失败 → `num_or_null()` 输出 `null`；
`doorOpen` 未接 → `null`；`battery/powerState` 无电池 → `null` / `mains`。

**source 约束**：只允许 `hardware` / `test`。网关 `ingest.normalize_source()`
把早期 `real` 映射为 `hardware`，其余（含缺失、`key_sim`）一律 `test`——**只会降级标注，不会洗白**。

## 七、已知限制（答辩主动说明）

1. **固件未在本机编译**：本机无 Hi3861 源码树。按 BearPi 官方 API 编写，
   引脚复用宏与 `WifiEvent` 回调返回类型可能需按 SDK 微调（`firmware/README.md` 第 4 节）。
2. **板端 `acknowledged` 的语义**：指“已成功上报网关（HTTP 200）”，
   与 APP 侧“家属确认”是两条线，台账确认由网关负责。
3. **单 PIR 无法定位**：`lastMotionZone` 固定 `unknown`，分区轨迹需多设备。
4. **无 RTC**：SNTP 失败时时间为开机计时，日报会错位。
5. **HTTP 短连接**：5 秒一帧适用；1 秒一帧建议 MQTT（本轮不实现）。
6. **无鉴权**：仅限局域网演示。
7. **门磁模拟会整帧降级为 test**：因为契约只有单一 `source` 字段，宁可整体标 test 也不冒充硬件。
