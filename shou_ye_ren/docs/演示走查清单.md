### 0.2 一条命令起前两样（推荐）

```powershell
cd D:\shadowlamp
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Siren -Voice
```

- `-Siren` 开分级声光提醒（这个开关**演示时必须加**，否则没声音）。
- `-Voice` 开语音播报（播音腔念告警内容）。
- **启动不会自动响**：带 `-Siren` 启动后，只有"启动之后新产生"的告警才会响；上一轮遗留的待确认告警只显示在 APP 里，不会一开机就哗啦响起来。要立刻听现有告警的声音，跑 `python scripts\siren.py on`。
- 脚本会新开两个窗口：`网关` 和 `模拟设备`。**这两个窗口别关**，演示结束再关。
- 电脑音量拉到 **100%**，别静音；笔记本最好插电（省电模式会压音量）。

### 0.2.1 预演很多遍：一条命令回到干净状态（推荐）

```powershell
cd D:\shadowlamp
powershell -ExecutionPolicy Bypass -File scripts
ehearse.ps1 -Siren -Voice
```

它比 `demo.ps1` 多做了三件“收拾现场”的事：

1. 先停掉上一轮的网关 / 模拟器（按状态文件 + 按命令行双重清理，防残留进程占端口）；
2. 清掉历史测试设备（`bench-01` / `bench-02`），避免 APP「我的」里冒出莫名其妙的离线设备；
3. 起来之后自动 `incident.py --type reset`，把开机瞬间可能重新入队的待确认告警清干净。

最后它会按顺序把 7 个演示场景的**原样命令**打出来，照着敲就行：

```

 6. 随身求助 L3  ->  python sim\incident.py --type sos

```

> 想保留上一轮数据就加 `-KeepData`；只想换端口加 `-Port 8790`。

## 3. L3 紧急求助 + 声音分级（2 分钟，演示重头戏）

> 这一步才是"开始报警"：前面启动服务是安静的，报警由事件（或手动开关）触发。

```powershell
cd D:\shadowlamp
python sim\incident.py --type sos      # 报警从这里开始
```

**手动开关（可选）**：

```powershell
python scripts\siren.py on      # 立刻播报现有待确认告警（含历史）
python scripts\siren.py off     # 立刻静音，正在响的也停
python scripts\siren.py auto    # 回到默认：只响之后新产生的告警
python scripts\siren.py status  # 看当前模式 + 待确认条数
```

**预期现象**（按顺序）：

1. 控制台：`-> 生成告警 EVT-XXXX (紧急求助：老人按下随身求助按钮)`。
2. **扬声器**：立刻 6 秒扫频警笛（600→1600Hz），紧接语音“紧急求助…请立即处理”，**每 7 秒一轮**（6 秒警笛 + 1 秒间隔），一直响到有人确认。
3. 网关窗口：`[siren] 开始分级提示：共 1 条，最高 L3（…）`，之后每轮一行 `播报 L3：…`。
4. APP「告警」页出现红色**紧急**卡片，首页顶部横幅变红「紧急告警待处理」。
5. 点进详情：「紧急求助…（超时未确认，已自动升级）」→ 填处置结果 → 「确认告警」。

**三档声音的节奏**（每一档都会**重复响到有人确认**，不是响一次就停）：

| 等级 | 声音 | 一轮多长 | 说明 |
|------|------|----------|------|
| L3 紧急 | 6 秒扫频警笛 + 语音 | 约 7 秒 | 接近不间断，像火警，必须处理 |
| L2 关注 | 三声中速提示音 + 语音 | 约 6.5 秒 | 尽快确认 |
| L1 提醒 | 两声轻提示音 + 语音 | 约 10 秒 | 方便时处理，不吓人 |

> 语音在后台播，不会把警笛节奏拖慢；如果某轮语音没放出声（电脑语音组件异常），警笛本身照常响。

### 3.1 六个场景的注入命令（评委让“随便演示一个”时按表走）

所有命令都在 `D:\shadowlamp` 下执行；也可用等价的 `powershell -ExecutionPolicy Bypass -File scripts\incident.ps1 -Type xxx`。

| 场景 | 命令 | 注入内容 | 网关判定 | 声音 | APP 上看到 |
|------|------|---------|---------|------|-----------|
| 温度偏高 | `python sim\incident.py --type temp` | 30.0℃ | `TEMP_WARM` L1 | 两声轻提示，约 10 秒一轮 | 首页温度 30.0℃ 变橙，「偏热，建议通风」 |
| 湿度偏高 | `python sim\incident.py --type hum` | 88% | `HUM_HIGH` **L2** | 三声，约 6.5 秒一轮 | 湿度 88% 变橙，「高于 80%，注意防潮」 |
| 光照异常 | `python sim\incident.py --type lux` | 夜间 02:30、420 lx | `LUX_NIGHT_HIGH` L1 | 两声轻提示 | 光照 420lx，「夜间偏亮，可能忘关灯」 |
| 门磁未关 | `python sim\incident.py --type door` | 门已开 12 分钟 | `DOOR_OPEN` L1 | 两声轻提示 | 门磁「已开」变橙，「门窗已持续开启 12 分钟」 |
| 夜间久无活动 | `python sim\incident.py --type night` | 卫生间 02:10 有活动、02:13 起无活动 | `NO_MOTION` **L3**（夜间卫生间） | 警笛，约 7 秒一轮 | 首页横幅红「紧急告警待处理」，告警页红色卡 |
| 随身求助 | `python sim\incident.py --type sos` | SOS 事件 | `SOS` L3 | 警笛，约 7 秒一轮 | 首页横幅红「紧急告警待处理」，红色紧急卡 |
| 疑似火情 | `python sim\incident.py --type fire` | 26℃ → 58℃ 陡升 | `TEMP_FIRE` L3 | 警笛，约 7 秒一轮 | 首页温度 58℃ 红 + 「疑似火情，先撤离后报警」 |

- **每个场景做完都点一下 APP「确认告警」**（声音立刻停），或用 `python sim\incident.py --type reset` 全部清掉再进下一个。
- 脚本每次注入前会先补一帧“门关着、有人活动”的归零帧，所以**连续演示多个场景不会互相干扰**。
- 门磁开着时不再叠加“无活动”提醒（门开=可能外出/在门边），一次只报最相关的那条。
- 一条告警没确认时，下一条会排队轮播，**先播最严重的那条**（L3 > L2 > L1）。
- 「特殊情况」不只是温度：湿度、光照、门磁三条都是 L1 环境提醒，演示时优先讲“哪一类问题对应哪一条动作建议”，这是评委最关心的落地感。

## 4. 确认闭环：响 → 停（1 分钟）

告警还在响的时候：

1. APP「告警」→ 点红色卡片 → 填「已上门查看，老人安好」→ 点「确认告警」。
2. **预期**：卡片变「已确认」；**扬声器当场停**；网关窗口出现 `[siren] 告警已全部解除，停止提示`。
3. 再点「提交处置并关闭」→ 卡片进「历史」，处置结果可查。

**要讲的点**：这是“闭环”——不是响完就完，必须有人确认并留下处置记录。

失败处理：若点确认报「网关无响应」，说明网关窗口被关了或端口不对，回第 0.2 步。

## 7. 关怀模式 / 多设备（各 30 秒）

- 「我的」→ 打开**关怀模式**：全 APP 字号放大 1.32 倍，给老人/评委看对比。

### 7.1 多设备到底是怎么用的（评委一定会问）

- **切换设备 = 换一位老人看**。「我的」里每个 `deviceId` 就是一台网关/一位老人；
  切到哪台，首页指标、报告、一键求助的归属就跟着换成哪台。
- **告警页默认是“全部设备”**：不管哪台设备出事都看得到，每张卡片上标了 `deviceId`，
  一眼知道“是谁家出的事、谁按的求助”。
  右上角胶囊点一下切到“仅当前设备”，再点回“全部设备”。
- **「我的」设备行现在直接写出状况**：`在线/离线 · 电量 · 待确认 N 条 · 最后上报时间`；
  待确认数变红就是这台出事了，不用点进去猜。
- **两台手机同时看**：只要两台手机都连同一个网关（同一个 IP:8780），
  在“全部设备”视图下都能看到同一条求助——**3 秒刷新一次**。
  但要如实讲清楚：这是**局域网轮询**，没有云端推送，手机 APP 必须在前台/不被系统冻结；
  真正做“远在外地的子女收到推送”需要云平台，本轮按赛题边界没做（PPT 第 16 页“边界”有写）。
- **演示设备清理**：`bench-01` / `bench-02` 是自检脚本留下的假设备，演示前清掉：
  `python scripts\clean_test_devices.py`（先 `--dry-run` 看会删什么）。

## 7.5 家庭组：一家人共享同一份监测（1 分钟）

> 这是“一个老人、多个监护人”的落地：子女、社区网格员进同一个组，看到的是同一份数据。

**操作顺序**
1. 首次打开 APP（或清过数据）会进「家庭组」引导页：两个大按钮「创建家庭组」「用密码加入」。
2. 点「创建家庭组」→ 填组名（如「张家」）与我的称呼（如「大女儿」）→ **确认创建** → 自动进首页。
3. 「我的」页顶部出现「家庭组」卡片：显示 `张家 · 户主`，点击进入详情。
4. 详情页看到：组名、我的身份、成员列表（户主/监护人）、**6 位加入密码**（大号数字 + 复制按钮）。
5. 点右上角「邀请家人」→ 底部浮层：大号密码 + 复制 + **二维码**（内容是网关地址 + 家庭组编号 + 密码）。
6. 另一台手机：同样进引导页 → 「用密码加入」→ 输入 6 位密码 + 称呼 → 加入 → 进首页，此时成员列表多一个「监护人」。

**要讲的点**
- 家庭组信息（成员、密码）存在**网关内存**里，重启网关会重置；这是“不搭云”的有意取舍，生产环境应换成云端账号体系（写进注释与文档，不装作已实现）。
- 二维码这一期只做展示与转发，**扫码自动解析没接**，加入仍走手输密码 —— 答辩被问“能不能扫码”就照实说。
- 密码只在局域网内有效，不承担账号鉴权职责；安全边界是“只在内网、只演示”。

**常见问题**
- 页面提示“网关重启过，这个家庭组已重置” → 网关重启过，重新创建或加入即可（这是内存态的正常表现）。
- 提示“没有找到这个家庭组，请核对 6 位密码” → 密码错或网关换过进程。

## 9. 故障速查

| 现象 | 原因 | 处理 |
|------|------|------|
| APP 显示「未连接网关」 | 网关没起 / 地址错 / 端口错 | 先开 `http://127.0.0.1:8780/health`，再核「我的」里的地址 |
| 首页指标全是「—」 | 模拟器没在跑，或数据被网关判为过期 | 看模拟设备窗口是否每 2 秒刷新 |
| 有告警但**没声音** | 起脚本时没带 `-Siren`；或系统静音；或播报被 `siren.py off` 关了 | `python scripts\siren.py status` 看模式；`siren.py on` 立刻生效；再查音量 |
| 刚启动就冒出一条“连续 X 分钟无活动” | 上一轮遗留的设备状态被当成连续观察（已修：静默从本次观察起点算，且前 180 秒不判时间累积型告警） | 升级到当前版本即可；临时处理：`python sim\incident.py --type reset` |
| 想让它**现在就响** | 告警是启动前就存在的（历史待确认，默认不自动响） | `python scripts\siren.py on` |
| 声音响了不停 | 没人确认（这是设计） | APP 里确认，或 `python sim\incident.py --type reset` |
| 声音一顿一顿、间隔 20 秒以上 | 旧版本网关（语音播报会阻塞警笛循环） | 升级到当前版本：语音已改后台播，警笛节奏不受影响 |
| 只响一声就不响了 | 旧版本 L3 警笛只放一次 | 升级到当前版本；新版每轮都会重新放 6 秒警笛 |
| `can't open file 'sim\incident.py'` | 当前目录不在项目里（没 `cd D:\shadowlamp`） | 用 `scripts\incident.ps1 -Type xxx`，或先 `cd D:\shadowlamp` |
| `python` 不是内部或外部命令 | PATH 没带 Python 3.8 | 用完整路径 `D:\HarmonySetup\Python38\python.exe` |
| 端口 8780 被占用 | 上一轮网关没关干净（新脚本会自动收掉并继续）；或别的程序真占了这个端口 | 若提示“已自动停掉”直接忽略；若列出的是别的程序，关掉它或换端口 `-Port 8790` |
| APP 连不上但 health 正常 | 模拟器网络没通到宿主机 | 「我的」里改用 `http://10.202.43.46:8780`（本机局域网 IP） |

## 7.6 报告长图导出（新交互）

原来点「导出图」只把 PNG 静默写进 APP 沙箱，相册里找不到。现在改成：

1. 报告页点右上「导出图」→ 立即弹出全屏预览：黑底半透明、中间白色卡片展示长图（标题 + 三块指标 + 近 7 日柱状 + 环境 + 结论 + 落款）。
2. 图片支持双指缩放（1x–4x），放大后可拖动；右上角大号 ✕ 关闭；底部两个 60vp 高的大按钮（适老化）。
3. 左「保存到相册」→ 系统弹出权限申请 → 允许后直接入相册；拒绝则提示并可「去设置」。
4. 右「分享给家人」→ 拉起系统分享面板（华为分享 / 复制 / 保存至图库 / 打印 / 添加到中转站），关面板自动回到报告页。
5. 长图实测 2520×2094（720vp 宽 @3.5 倍屏，357KB），落款含生成时间、网关地址、数据来源，便于评审核对。

### 设备切换验收要点（2026-10-27 补）

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 「我的」→ 设备切换 | 每台设备一行：编号 + 来源标签（真实设备/模拟演示/未上报）+ 在线/离线 + 电量 + 最后上报 |
| 2 | 点「切换」到离线设备 | 绿字「已切换到 xxx」3 秒消失；回「首页」立即显示「设备离线 · 数据已过期」 |

### 7.7 语音播报与一键拨号（2026-10-27 新增）

1. 启动网关与模拟器（和 7.1 一样），确保 APP「我的」里网关地址正确。
2. 切到「告警」页，保持 APP 在前台。
3. 新开一个窗口注入一条求助：
   ```
   cd D:\shadowlamp
   python sim\incident.py --type sos
   ```
4. 预期：APP 3 秒内出现新告警卡片（「新」角标 + 待确认）。
5. **点开**这条告警 → 预期**听到中文语音**「警告，监测到紧急求助，请立即处理」
   （若模拟器/真机静音请先开媒体音量）。关闭的历史告警点开不会再念，属预期。
6. 下拉到「建议措施」下方 → 点红色「一键呼叫家属」。
   - 真机：拉起系统拨号盘，号码预填，用户点绿色按钮才会真正拨出。
   - 模拟器：没有拨号应用，会提示「这台设备不支持拨号，请手动拨打 13800138000」，
     APP 不崩溃，属预期现象（可在答辩时主动说明这是模拟器限制）。
6. 回到列表继续处置（确认 → 填写结果 → 提交关闭），语音不会重复播同一条。
