# 个性化阈值：完整代码 + 测试引导

> 目标：你在模拟器上能"改一个阈值 → 看到判定结果真的跟着变"。
> 这份文档里的代码就是工程里**正在跑的那一份**（不是示意代码），直接对照文件即可。

---

## 一、接口契约（先看懂这一层）

| 项 | 值 |
|---|---|
| 读取 | `GET /api/v1/config/threshold` → 返回全部阈值 JSON |
| 写入 | `POST /api/v1/config/threshold`（**注意是 POST，不是 PUT**） |
| 请求体 | 只放要改的键，其余保持不变，例如 `{"temp_high":33}` |
| 生效 | 立即生效，落 sqlite（`kv` 表），网关重启仍保留 |
| 校验 | 分钟类必须 > 0；小时类 0–23；`temp_offset` ±15；`hum_offset` ±30；否则 400 `BAD_CONFIG` |

常用键（全部是有默认值的类字段，见 `gateway/config.py` 的 `Thresholds`）：

| 键 | 含义 | 默认 |
|---|---|---|
| `no_motion_min` | 白天连续无活动（分钟） | 5 |
| `night_no_motion_min` | 夜间非卫生间无活动 | 3 |
| `night_bathroom_min` | 夜间卫生间无活动（最危险） | 2 |
| `door_open_max_min` | 门窗持续开启 | 10 |
| `away_max_min` | 疑似外出最长容忍 | 120 |
| `sleep_gap_min` | 睡眠时段超长静默 | 360 |
| `escalate_min` | 待确认多久自动升级 | 5 |
| `temp_high` / `temp_low` | 温度上下限 | 35 / 16 |
| `hum_high` / `hum_low` | 湿度上下限 | 80 / 25 |
| `temp_offset` / `hum_offset` | 便携传感器整体偏移校正 | 0 |
| `nap_start_hour` / `nap_end_hour` | 午睡时段（不判无活动） | 13 / 15 |
| `sleep_start_hour` / `sleep_end_hour` | 睡眠时段 | 23 / 7 |

## 二、APP 侧代码

### 2.1 `model/Models.ets`：只需要一个"键值都是数字"的宽松结构

工程里为了避免 `arkts-no-untyped-obj-literals`，`savePersonal()` 直接**拼 JSON 字符串**，所以模型层不用改。
如果你偏好强类型，可以加：

```typescript

export interface ThresholdPatch {
  no_motion_min?: number;
  night_no_motion_min?: number;
  night_bathroom_min?: number;
  door_open_max_min?: number;
  temp_high?: number;
  temp_low?: number;
  hum_high?: number;
  hum_low?: number;
  temp_offset?: number;
  hum_offset?: number;
}
```

### 2.2 `service/ApiClient.ets`：一个方法搞定读写

```typescript
/** 下发阈值（只带要改的键）；返回 true 表示网关 2xx */
static async applyConfig(json: string): Promise<boolean> {
  const text: string = await ApiClient.request(
    '/api/v1/config/threshold', http.RequestMethod.POST, json);
  return text.length > 0;
}

/** 读当前阈值（个性化页进来时回填输入框用） */
static async getThresholds(): Promise<string> {
  return await ApiClient.request('/api/v1/config/threshold', http.RequestMethod.GET, '');
}
```

> `ApiClient.request()` 内部统一处理了 baseUrl、4 秒超时、异常吞掉返回空串。
> 所以 `applyConfig` 返回 `false` 只代表"没拿到响应"，UI 层统一提示"网关不可达"。

**保存逻辑**（只拼用户真填了的项）：

```typescript
async savePersonal(): Promise<void> {
  const parts: string[] = [];
  if (this.tempHighText.length > 0) { parts.push('"temp_high":' + this.tempHighText); }
  if (this.humHighText.length > 0) { parts.push('"hum_high":' + this.humHighText); }
  if (this.noMotionText.length > 0) { parts.push('"no_motion_min":' + this.noMotionText); }
  if (parts.length === 0) { this.personalTip = '没有填写内容，沿用默认阈值'; return; }
  const body: string = '{' + parts.join(',') + '}';
  const ok: boolean = await ApiClient.applyConfig(body);
  this.personalTip = ok ? '已保存，按你的设置判定' : '保存失败：网关不可达';
}
```

> 用字符串拼 JSON 而不是对象字面量，是为了绕开 ArkTS 的
> `arkts-no-untyped-obj-literals` 检查——工程里所有回调体都是这个套路。

## 三、网关侧代码（已经在跑）

`gateway/api.py`（路由表里注册，`POST`）：

```python
def set_thresholds(self, params, body):
    if not isinstance(body, dict) or not body:
        raise ApiError(400, "BAD_REQUEST", "请求体必须包含要更新的阈值字段")
    merged = dict(self.store.thresholds().to_dict())   # 先取当前值
    merged.update(body)                                # 再叠加本次改动
    th = Thresholds.from_dict(merged)
    for key in ("no_motion_min", "night_no_motion_min", "night_bathroom_min",
                "away_max_min", "door_open_max_min", "escalate_min", "sleep_gap_min"):
        if getattr(th, key) <= 0:
            raise ApiError(400, "BAD_CONFIG", "%s 必须为正整数" % key)
    for start_key, end_key in (("sleep_start_hour", "sleep_end_hour"),
                               ("nap_start_hour", "nap_end_hour")):
        if not (0 <= getattr(th, start_key) <= 23 and 0 <= getattr(th, end_key) <= 23):
            raise ApiError(400, "BAD_CONFIG", "小时必须在 0~23")
    self.store.save_thresholds(th.to_dict())
    return {"ok": True, "thresholds": th.to_dict(), "appliedAt": util.iso_now()}
```

`gateway/store.py`：

```python
def save_thresholds(self, data):
    th = Thresholds.merge(data)
    self.kv_set("thresholds", th.to_dict())     # 落 kv 表，重启保留
    return th
```

判定侧不用改：`Engine.on_snapshot()` 每帧开头 `th = self.store.thresholds()`，
所以**保存后下一帧就按新阈值判**。

## 四、测试引导（照着走，10 分钟）

> 三个窗口：**A 服务窗**（起网关/构建）、**B 注入窗**（注入场景）、**C 模拟器**。A/B 都先 `cd D:\shadowlamp`。

### 步骤 1：用 curl 先验证接口（A 窗，不依赖 APP）

```powershell
cd D:\shadowlamp
curl http://127.0.0.1:8780/api/v1/config/threshold            # 看全部阈值
curl -X POST http://127.0.0.1:8780/api/v1/config/threshold `
     -H "Content-Type: application/json" -d '{\"temp_high\":33}'
```
**预期**：第二次返回 `"ok":true`，里面 `temp_high` 变成 33，`appliedAt` 是当前时间。

### 步骤 2：验证校验分支（故意传错）

```powershell
curl -X POST http://127.0.0.1:8780/api/v1/config/threshold -H "Content-Type: application/json" -d '{\"no_motion_min\":0}'
```
**预期**：`400 BAD_CONFIG，no_motion_min 必须为正整数`（说明后端不是"照单全收"）。

### 步骤 3：APP 里改阈值（C 模拟器）

1. 「我的」→ 滑到 **个性化设置**；
2. 温度上限填 `33`；(白天无活动留空)
3. 点 `保存阈值`。
**预期**：卡片下方出现绿字"已保存，按你的设置判定"。

### 步骤 4：验证"新阈值真的参与判定"（B 注入窗）

```powershell
cd D:\shadowlamp
python sim\incident.py --type temp      # 注入 36℃
```
- 阈值 33：36 > 33 → **L1 环境提醒**（首页温度变红 + 顶部黄条）
- 把阈值改回 35 再注入：36 > 35 → 依然 L1；改成 40：36 < 40 → **不再报警**（这一步最能说明"阈值生效"）

验证路径（A 窗看库）：
```powershell
python -c "import sqlite3;c=sqlite3.connect('data/gateway.db');print(c.execute(\"select event_id,type,level,message from alarm order by rowid desc limit 1\").fetchone())"
```

### 步骤 5：验证无活动阈值

```powershell
python sim\incident.py --type idle       # 注入"白天客厅连续 10 分钟没动"
```
- `no_motion_min=5`（默认）→ L2 关注
- 改成 `no_motion_min=15` → 同样注入**不再报警**（10 < 15）
- 改回 5 → 又报警

> 注意：把阈值改大之后已存在的待确认告警不会自动消失，先 `--type reset` 再注入才干净。

### 步骤 6：验证重启保留（可选，但答辩加分）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Stop
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Siren -Voice
```

**预期**：`temp_high` 仍是你改过的值（存在 sqlite 的 `kv` 表）。

## 五、排错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 点保存没反应 | 网关地址没填对 / 网关没起 | 「我的」点 `保存并测试连接`，看是否绿字成功 |
| 保存成功但判定不变 | 改的是 `temp_high`，注入的是湿度场景 | 看注入脚本打印的"期望"行，确认改的键对得上 |
| 返回 400 `BAD_REQUEST` | 请求体是空对象 `{}` | 至少带一个键 |
| 返回 400 `BAD_CONFIG` | 传了 0 / 负数 / 小时 >23 | 按提示改，分钟类必须 ≥1 |
| 改完还是老结果 | 网关有 180 秒预热期（重启后） | 等 3 分钟，或先演示瞬时类场景 |
| APP 输入框留空却提示"没有填写内容" | 三个框全空 | 正常提示，不会覆盖默认值 |
