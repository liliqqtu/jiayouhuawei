## 3. 你只需要实现 3 个接口

| 方法 | 路径 | 用途 | 频率 |
|---|---|---|---|
| POST | `/api/v1/snapshot` | 上报一帧传感器数据（16 字段） | 建议 2–5 秒 |
| POST | `/api/v1/events` | 上报直接事件（求助键 / 烟感 / 燃气） | 触发即报 |
| GET | `/api/v1/alarms/active?...` | **下行**：问“我这条告警有人处理了吗” | 10 秒一次 |

字段定义、`null` 规则、`source` 取值、重试与缓存规则，全在 `docs/hardware-contract.md`，这里不重复。

三条容易被忽略的硬规则：

1. **`source` 只能是 `hardware` 或 `test`**。板子真实采集填 `hardware`；`sim/` 打的帧是 `test`。APP 首页与告警卡会按它显示“真实采集 / 测试/模拟”，填错等于数据造假。
2. **未知值写 `null`，不要写 0 或不填**。例如没接门磁就 `"doorOpen": null`，APP 显示“—”而不是“已关”。
3. **`seq` 在同一设备内单调递增**；网关按 `(deviceId, seq)` 去重，重复上报不会重复计数。断网重连后允许重发，但别把 `seq` 重置回 0。

## 4. 固件现状（已写完，未编译）

| 文件 | 职责 |
|---|---|
| `app_main.c` | `SensorTask`（只采集，不碰网络）+ `UploadTask`（组帧上传、失败进环形缓存） |
| `env.c/h` | SHT30（I2C 0x44）温湿度 + BH1750（0x23）光照，失败写 `null` |
| `drv.c/h` | PIR（GPIO11）、求助键（GPIO12，50ms 消抖）、LED（GPIO2）、门磁（可选，GPIO10） |
| `biz.c/h` | 业务状态：无活动计时、门开计时、求助键锁存、告警状态机（ACTIVE/ACKNOWLEDGED/CLOSED） |
| `local_rule.c/h` | **板端本地兜底判定**：断网时按阈值自己判 L1/L2/L3，驱动 LED 闪烁 |
| `net.c/h` | Wi-Fi STA 连接、`http_do()` 通用请求、JSON 取字段、16 帧环形缓存 |
| `sntp.c/h` | SNTP 对时，输出 ISO8601 时间戳（板子无 RTC） |
| `log.h` | `LOGI/LOGW/LOGE`，`#JSON#` 标记便于串口抓报文 |
| `BUILD.gn` | 已列 7 个 `.c`（含 `env.c` `local_rule.c`），接进 Hi3861 源码树即可 |

**职责边界（重要）**：网关是“判定权威”，板端 `local_rule` 只是**断网兜底**（本地响 LED/蜂鸣，不替代网关的三档判定与融合规则）。别把完整判定搬上板子，否则两边结论会打架。

## 6. 联调四步（从易到难，出问题好定位）

先起服务（另开窗口）：

```powershell
cd D:\shadowlamp
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Siren -Voice
```

**第 1 步 · 电脑先假装是板子**（排除固件因素）

```powershell
python sim\incident.py --type temp      # 电脑发一帧"温度偏高"
```

浏览器开 `http://127.0.0.1:8780/` 看板应出现告警。这一步通过 = 网关/APP 链路没问题。

**第 2 步 · 用 UDP 代替板子发帧**（网关三个入口里，UDP 是板子最简单的通道）

```powershell
# 注册 UDP 端口要在启动时加 --udp-port 9998（demo.ps1 已带）
python -c "import socket,json,time; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.sendto(json.dumps({'deviceId':'bearpi-001','ts':time.strftime('%Y-%m-%dT%H:%M:%S+08:00'),'seq':9001,'pirDetected':True,'temperature':23.5,'humidity':50.0,'lux':120.0,'doorOpen':False,'source':'hardware'}).encode(),('127.0.0.1',9998)); print('udp sent')"
```

网关日志出现 `udp snapshot` 即通道正常。

**第 3 步 · 串口直连**（板子还没连 WiFi 时最快）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Stop
python run_gateway.py --port 8780 --lan --serial COM3 --baud 115200
```

固件里 `LOGI` 打出的 `#JSON#` 行会被网关直接解析；串口能通说明组帧正确，剩下只是网络。

**第 4 步 · 板子 WiFi 直连**

烧录后看串口：

1. `[net] wifi connected ip=...` → 拿到 IP
2. `[sntp] 2026-11-02T14:03:00+08:00` → 时间对（没有时间戳会判 `timeAdjusted`）
3. 网关日志应出现 `POST /api/v1/snapshot 200`，`source=hardware`
4. 网页看板“这台网关带的设备”里出现 `bearpi-001 · 在线`，且“数据来源”显示 **真实采集**

## 8. 已知未验证 / 风险（如实写，别在答辩时说成已实现）

1. **固件未编译过**：本机没有 Hi3861 源码树，`BUILD.gn` 与 C 代码只做过静态检查。
2. **板端语音未实现**：本地播报目前由**网关**的电脑扬声器代播（`--voice`），板子上只有 LED/蜂鸣器。若要在板端出声，需要额外的音频方案（Hi3861 无音频外设）。
3. **单 PIR 无定位**：`lastMotionZone` 靠配置推断，实际填 `unknown` 或按房间预置；不要声称能识别“在哪个房间摔倒”。
4. **无 RTC**：断电后必须先 SNTP 对时，否则时间戳可能错，网关会打 `timeAdjusted` 标。
5. **HTTP 短连接**：1–5 秒一帧用短连接开销可接受；若要 1 秒级高频上报，应换 MQTT（本项目未实现）。
6. **无鉴权**：只允许局域网内使用，不要暴露到公网。

## 9. 禁区（会直接扣分或造成数据造假）

1. **禁词**：全仓禁止出现“跌倒 / 昏迷 / 摔倒”等医学结论词（`python scripts\check_words.py` 会扫，当前 0 命中）。
2. **不要造数据**：没有传感器就写 `null`，不要写 0、不要写假值、不要把 `test` 帧标成 `hardware`。
3. **不要绕过网关直连数据库**：写入只走 HTTP/UDP/串口三个入口，网关统一打 `created_at`、去重、判定。
4. **不要把 `seq` 重置**：会触发网关“2 分钟内重复视为重试”的保护，导致数据被丢弃。
5. **不要动 `data/*.db`**：演示库是现场数据，改坏了演示就没了（要清就用 `python scripts\clean_test_devices.py`）。

## 12. 卡住时按这个顺序排查

| 现象 | 先查 | 再查 |
|---|---|---|
| 板子连不上 WiFi | SSID 是否 2.4G、密码长度 | 路由器是否开了 MAC 过滤 |
| 能连 WiFi 但上报 401/404 | `CFG_GATEWAY_IP:PORT` 是否是电脑当前 IP | 电脑防火墙是否放行 8780 |
| 上报成功但看板没数据 | 网关日志有没有 `POST /api/v1/snapshot` | `source` 是不是写成了别的值 |
| APP 显示“测试/模拟” | 帧里 `source` 字段 | 是否走的是 UDP/串口但 `source` 没填 `hardware` |
| 告警不出现 | 是否在网关启动 180 秒预热期内 | 时间戳是否比网关时间晚 5 分钟以上 |
| 板端 LED 不亮 | `local_rule` 是否被调用、阈值宏是否合理 | GPIO 编号与原理图是否一致 |
