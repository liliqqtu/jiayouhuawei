# 部署操作手册

> 三端关系：`开发板` →（Wi-Fi/串口）→ `PC 网关` →（局域网 HTTP）→ `鸿蒙 APP`
> 任何一段断开，前一段仍能独立工作（这是设计的核心）。

---

## 一、南向固件：编译与烧录

### 1. 改配置（3 分钟）

打开 `firmware/config.h`，只改这四行：

```c
#define CFG_WIFI_SSID       "你的2.4G-WiFi"
#define CFG_WIFI_PASSWORD   "密码"
#define CFG_GATEWAY_IP      "192.168.x.x"   // 网关启动时打印的 IP
#define CFG_DOOR_MODE       0               // 0=没接门磁，输出 null
```

> Hi3861 **只支持 2.4G**，5G 连不上。

### 2. 放进工程

```text
applications/BearPi/BearPi-HM_Nano/sample/shadow_lamp/
├── app_main.c  biz.c  drv.c  env.c  net.c  sntp.c
├── biz.h  drv.h  env.h  net.h  sntp.h  config.h  log.h
└── BUILD.gn
```

编辑同级 `sample/BUILD.gn`，在 `deps` 中加：

```gn
"//applications/BearPi/BearPi-HM_Nano/sample/shadow_lamp:shadow_lamp",
```

### 3. 编译烧录

1. VS Code 打开 OpenHarmony 源码根目录（已装 DevEco Device Tool）。
2. 底部状态栏选 Board = `Hi3861`，串口选 `COMx`。
3. `Build` → 成功后 `Upload`。
4. 若提示端口占用：先关串口助手再烧。

### 4. 用串口验证（115200-8-N-1）

```
[0][v0.1.0][drv][INFO] init ok
[0][v0.1.0][env][INFO] sht30=1 bh1750=1
[0][v0.1.0][app][INFO] ===== ShadowLamp v0.1.0 boot =====
[3][v0.1.0][net][INFO] task start, gateway=192.168.1.100:8780
[8][v0.1.0][sntp][INFO] time synced: 2026-11-02T14:03:00+08:00
[9][v0.1.0][upload][INFO] pir=0 temp=23.4 hum=51.0 door=null status=none
#JSON#{"deviceId":"bearpi-001",...}
```

- `sht30=0` 表示模块没探到 → 温度字段会是 `null`（正常，不是故障）
- 把手放在 PIR 前 → `pir=1`，`lastMotionTs` 变化
- 静置超过 `CFG_NO_MOTION_MS` → `[biz][WARN] alarm NO_MOTION status=active`，LED 闪

## 二、网关：启动与模式切换

### 模式 0：一键演示（推荐现场用）

```powershell
cd software
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1        # 起网关+看板+模拟器
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Stop  # 全部停掉
```

它会先查端口占用、再起 `run_gateway.py --lan --udp-port 9998`、最后起模拟器循环，
并把「本机看板 / 手机看板 / APP 网关地址」三个地址一次性打出来。
日志在 `data/demo_gateway.log` 与 `data/demo_sim.log`。

### 模式 1：HTTP（默认，固件直接 POST）

```powershell
cd software
python run_gateway.py --lan
```

### 模式 2：Wi-Fi UDP（固件把 JSON 打到 UDP 9999）

```powershell
python run_gateway.py --lan --udp-port 9999
```

固件侧把 `net.c::http_post()` 换成 UDP `sendto`（或用官方 `udp_demo` 改）。

### 模式 3：USB 串口桥接（降级方案，最稳）

```powershell
python run_gateway.py --serial COM3 --baud 115200
```

网关会解析串口里 `#JSON#` 开头的行，普通调试日志自动忽略。
**不需要 pyserial**（没有时用系统 `mode` + 设备文件）。

### 混合模式（推荐演示用）

```powershell
python run_gateway.py --lan --udp-port 9999 --serial COM3
```

启动横幅会打印 `接入通道: UdpIngest / SerialIngest`。

### 分级播报：启动 ≠ 报警（重要）

```powershell
python run_gateway.py --lan --siren --voice
```

- `--siren` 打开本机分级播报（L3 扫频警笛 / L2 三声 / L1 两声），`--voice` 加语音。
- **启动时不响**：只播报"启动之后新产生"的告警。启动前就存在的待确认告警属于历史，
  只在 APP / 看板里显示，不会一开机就吵——现场演示和录屏都需要这个行为。
- 注入场景（不用先 cd，任何目录都能跑）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\incident.ps1 -Type temp   # 高温
powershell -ExecutionPolicy Bypass -File scripts\incident.ps1 -Type sos    # 求助
powershell -ExecutionPolicy Bypass -File scripts\incident.ps1 -Type reset  # 复位
```

- 要立刻播报现有告警（含历史）或静音，用运行期开关：

```powershell
python scripts\siren.py on       # 立刻播报现有待确认
python scripts\siren.py off      # 立刻静音（正在响的也停）
python scripts\siren.py auto     # 回到默认：只响新告警
python scripts\siren.py status   # 当前模式 + 待确认条数
```

- 等价 HTTP 接口：`GET /api/v1/siren` 查状态，`POST /api/v1/siren {"mode":"on|off|auto"}` 切模式。
  网关没带 `--siren` 时返回 `409 NO_SIREN`，不会假装成功。
- **重启后前 3 分钟只做“瞬时判定”**：网关重启时库里的设备状态是上一轮留下的，
  「连续多久没活动」这类时间累积判定不能拿旧时间戳算（否则一启动就报一条
  `卫生间连续 7 分钟未检测到活动` 并响起来）。现在静默计时从“本次连续观察起点”算，
  且观察起点后 180 秒内不判这类告警；温度 / 可燃气 / 烟雾 / 求助等瞬时告警不受影响。
  日志里会出现 `[rules] 首次实时上报，180 秒内不判时间累积型告警`。
- 端口被占用时会直接报错退出（Windows 下两个进程能绑同一端口，后起的会"假启动"，
  请求却被旧进程接走），提示你跑 `scripts\demo.ps1 -Stop` 或换 `--port`。

### 下行确认（只有真机才有用）

网关侧不用做任何额外配置：`/api/v1/alarms/active` 默认就在。真机要看到“家属确认后板子停响”，
需要固件是带 ACK 轮询的版本（`CFG_ACK_POLL_MS` 默认 10 秒），并保证：

1. `CFG_GATEWAY_IP/PORT` 与网关实际监听一致（默认 8780）；
2. 板子 `deviceId` 与 APP 里看的是同一台（`CFG_DEVICE_ID`）；
3. 蜂鸣器若没接，只有 LED 会变化（`CFG_BUZZER_EN=0` 时静音）。

手工验证（不用板子）：

```powershell
curl.exe "http://127.0.0.1:8780/api/v1/alarms/active?deviceId=shouye-01"
# 期望：{"deviceId":..., "pendingCount":1, ...}；APP 确认后再请求 -> pendingCount 0
```

### 自检

```powershell
curl.exe http://127.0.0.1:8780/health
curl.exe http://127.0.0.1:8780/api/v1/snapshot
curl.exe http://127.0.0.1:8780/api/v1/alarms?status=pending
```

### 没有硬件时

```powershell
python run_sim.py --scenario night --base 02:10   # 触发 L3
python run_sim.py --loop                          # 持续心跳
```

模拟数据固定 `source=test`，APP 会显示“测试/模拟”角标。

## 三、APP：改 IP 与安装

1. DevEco Studio 打开 `D:\DevEcoProjects\shadow-lamp-app`。
2. 登录华为账号（自动签名）→ Run 到模拟器。
3. 打开 APP →「我的」→ 网关地址填 `http://电脑IP:8780` → **保存并测试连接**。
4. 回首页，应看到五指标与更新时间。

> 换网络只改这一页，不用重新编译。
> 校园网常有客户端隔离，连不上就用**手机热点**（IP 变 192.168.x.x）。

命令行构建（不打开 IDE）：

```powershell
powershell -ExecutionPolicy Bypass -File software\scripts\build_app.ps1
```

---

### 改完 APP 代码怎么重新出 HAP

工作区源码（`software/app/ShadowLamp`）和 DevEco 工程（`D:\DevEcoProjects\shadow-lamp-app`）
是镜像关系，**不会自动同步**。改完源码走一条命令即可同步 + 构建：

```powershell
cd software\scripts
powershell -ExecutionPolicy Bypass -File sync_app.ps1 -Build
```

产物：`D:\DevEcoProjects\shadow-lamp-app\entry\build\default\outputs\default\entry-default-unsigned.hap`。
只同步 `ets/`、`resources/`、`AppScope/` 与 `module.json5`，不会覆盖工程里的签名配置。

## 四、降级切换决策树

```
APP 连不上网关？
├─ 电脑浏览器打开 http://127.0.0.1:8780/health 正常？
│   ├─ 正常 → 手机与电脑不同网段 / 校园网隔离
│   │           → 手机热点；或网关 --lan 重启并放行防火墙 8780
│   └─ 不正常 → 网关没起 → 重新 run_gateway.py
└─ 板端数据到不了网关？
    ├─ 串口有 #JSON# 输出 → 网络问题 → 切 --serial COM3 桥接
    └─ 串口没有输出   → 固件/烧录问题 → 看第 1 节串口日志
```

**降级只影响链路，不影响数据真实性标注**：桥接模式下 `source` 仍由固件决定。

## 五、一键自检清单

| 检查 | 命令/操作 | 期望 |
|---|---|---|
| 网关活着 | `curl /health` | `{"ok":true,...}` |
| 有数据 | `curl /api/v1/snapshot` | 含 `seq`、`source` |
| 设备在线 | `curl /api/v1/device` | `online:true` |
| 告警可查 | `curl /api/v1/alarms` | `items` 数组 |
| APP 连接 | 「我的」→ 测试连接 | “连接成功” |
| 端到端 | PIR 走动 | 首页“最后活动”刷新 |
