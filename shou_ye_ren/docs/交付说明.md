## 一、数据字段说明

三端共用同一套契约，字段名与《需求符合性矩阵》05 表一致。**未知值一律 `null`，不填 0**。

### 1. SensorSnapshot（设备快照，1~5 秒一帧）

| 字段 | 类型 | 说明 |
|---|---|---|
| `deviceId` | string | 设备编号，如 `bearpi-001` |
| `ts` | string | ISO8601 带时区：`2026-11-02T14:03:00+08:00` |
| `seq` | int | 上电从 1 递增，用于补传排序与去重 |
| `pirDetected` | bool | 本次是否检测到人体活动 |
| `lastMotionTs` | string/null | 最后一次活动时间 |
| `lastMotionZone` | enum/null | `living/bedroom/bathroom/kitchen/entry/unknown` |
| `temperature` / `humidity` / `lux` | number/null | 未接该传感器则为 null |
| `doorOpen` | bool/null | 未接门磁为 null |
| `battery` | number/null | 市电供电时为 null（**不填 0**） |
| `powerState` | enum/null | `mains/usb/battery` |
| `rssi` | int/null | 信号强度，dBm |
| `online` | bool | 设备自报在线 |
| `source` | enum | **`real` 真实 / `key_sim` 按键模拟 / `test` 测试 / `history` 历史** |
| `fwVersion` | string | 固件版本 |

### 2. AlarmEvent（告警，全生命周期）

| 字段 | 说明 |
|---|---|
| `eventId` | `EVT-YYYYMMDD-NNNN`，网关生成 |
| `ts` | 触发时间 |
| `type` | `NO_MOTION / SOS / TEMP_HIGH / TEMP_LOW / HUM_HIGH / HUM_LOW / DOOR_OPEN / AWAY_LONG / GAS / SMOKE` |
| `level` | `L1 提醒 / L2 关注 / L3 紧急` |
| `message` | 面向家属的自然语言 |
| `status` | `pending 待确认 → acknowledged 处理中 → closed 已关闭` |
| `ackTs` / `closedTs` | 确认 / 关闭时间 |
| `handleType` | `visited / phone / false_alarm / community / other` |
| `handleResult` | ≤200 字处置结果 |
| `source` | 同上，非 `real` 的会在界面标注 |

### 3. ActivityRecord（活动明细，用于统计）

`ts`、`zone`、`eventType(motion/door/button)`、`countWindow`、`source`。

### 4. 判定规则（板端兜底 + 网关权威）

- 板端（`local_rule.c`，断网也能判）：
  - 温度/湿度/门磁按 `config.h` 阈值给出 L1/L2/L3 本地等级，带 30 秒确认窗与 60 秒回差；
  - 疑似火情（≥55℃ 或 3 分钟升 8℃）与求助直接 L3，不等确认；
  - `now - lastMotionTs ≥ 阈值` → **NO_MOTION（疑似长时间无活动）**；按键 → **SOS**；
  - 本地只驱动声光（LED 按等级闪、蜂鸣器可选），事件仍全量上报。
- 网关：三档 + 三条融合（外出抑制 / 夜间加权 / 冷却去重）+ 超时自动升级；
  **最终等级、去重、升级只认网关**，板端本地等级不写进台账。
- 下行确认：板端每 10 秒拉 `/api/v1/alarms/active`，`pendingCount=0` 就停响、LED 常亮。
- **严禁**把 NO_MOTION 表述成医学结论（本项目只报“疑似长时间无活动”，不判断体态）。

## 二、部署步骤

### 步骤 1：起网关（电脑）

```powershell
cd software
python run_gateway.py --lan
```

记下打印的 `http://192.168.x.x:8780`。**必须 `--lan`**，否则手机/开发板连不上。

### 步骤 2：烧固件（开发板）

1. 改 `firmware/config.h` 三行：Wi-Fi 账号、密码、网关 IP。
2. 按 `firmware/README.md` 第 2 节把目录放进 BearPi 示例工程并改 `BUILD.gn`。
3. DevEco Device Tool 编译 → 烧录。
4. 串口应看到 `[net] connected` 与 `[sntp] synced`。

### 步骤 3：装 APP（手机/模拟器）

1. DevEco Studio 打开 `D:\DevEcoProjects\shadow-lamp-app`。
2. 登录华为账号（自动签名）→ Run。
3. 「我的」→ 填 `http://电脑IP:8780` → 保存并测试连接。

### 步骤 4：验收（3 分钟）

| 操作 | 预期 |
|---|---|
| PIR 前走动 | 首页“最后活动”刷新，`pirDetected=true` |
| 静置超过阈值 | 板端 LED 闪烁；APP 告警页出现 L2 |
| 按板载键 | 板端快闪；APP 出现 L3「紧急求助」 |
| APP 点开告警 → 确认 → 填处置 → 提交 | 状态变“已关闭”，重启 APP 仍能查到 |
| 拔掉电脑网线 | 板端继续采集/闪灯；APP 显示离线并展示本地缓存 |
| 浏览器打开 `http://电脑IP:8780/` | 看到“一切正常/待确认 n 条”看板，3 秒自动刷新 |

## 三、降级方案

按“越往后越稳”的顺序设计，任何一环失效都有下一步：

| 层级 | 主方案 | 降级 | 触发条件 |
|---|---|---|---|
| 设备↔网关 | Wi-Fi + HTTP | USB 串口 + PC 桥接（网关把串口行当 JSON 收） | 10/29 前 Wi-Fi 仍不稳 |
| 网关↔APP | 局域网 HTTP | 同机 `127.0.0.1` + 模拟器 | 校园网客户端隔离 |
| APP 数据 | 网关实时 | **本地 RDB 缓存**（已实现） | 网关不可达 |
| 板端告警 | 声光 + 上报 | **纯本地声光**（不依赖网络） | 断网 |
| 时间 | SNTP | 网关纠偏未来时间 | 无外网 |

**现场最实用的一条**：如果校园网隔离，直接用**手机热点**，电脑连上去，IP 变成 `192.168.x.x`，最稳。

## 四、已知限制（答辩要主动说）

1. **固件未在本机编译验证**。本机没有 Hi3861 源码树；代码按 BearPi 官方 API 编写，
   引脚复用宏、`WifiEvent` 回调返回值可能因 SDK 版本不同需微调（`firmware/README.md` 第 4 节列了对照表）。
2. **单 PIR 无法定位**：`lastMotionZone` 固定 `unknown`；“活动轨迹”要靠多设备/多路 PIR。
3. **不做体态识别**：物理上做不到，只输出“疑似长时间无活动”，由人确认。
4. **无 RTC**：SNTP 失败时时间会落到 1970 年，日报错位。
5. **HTTP 短连接**：5 秒一帧够用；1 秒一帧建议改 MQTT（网关已预留主题）。
6. **离线处置是"暂存补发"而非实时生效**：断网时 APP 把确认/处置写进本地队列
   （`service/Outbox.ets`），每 9 秒尝试补发一次；补发成功前本地只是乐观显示，
   网关台账仍以自己库里的状态为准。这是刻意取舍——宁可晚 10 秒，也不做两套状态。
7. **无鉴权**：仅限局域网演示，公网暴露前必须加 token。

## 设备切换模块升级（2026-10-27）

### 改了什么
1. **添加设备不再前端造假**：填编号 → `POST /api/v1/devices` 占位登记 → 返回成功才入列表；
   网络不通时 Toast + 红字「无法连接网关，请先保存并测试连接」。列表里显示「未上报」标签，
   不伪造任何传感器读数。
2. **切换即全局刷新**：选中 ID 写 Preferences（`Settings.setDevice`）+ AppStorage 的
   `deviceId`、`dataVersion` 双信号，首页/告警页 `@Watch` 后立即重取；切换成功绿字
   「已切换到 xxx」，3 秒后自动消失。
3. **10 秒轮询 + 生命周期**：只有停在「我的」页才开轮询（`@Prop active` + `onActiveChange`），
   离开或组件销毁（`aboutToDisappear`）必清定时器；网关离线时保留上次列表并红字标注
   「网关离线：下面的是上次取到的列表，状态可能已过期」。
4. **source 标签**：网关 `/api/v1/devices` 每台设备带 `source`（取自最新一帧快照），
   APP 显示「真实设备」/「模拟演示」/「未上报」——数据诚信要求落到设备维度。
5. **关怀模式 1.2 倍**：`Theme.largeScale` 统一为 1.2，导航图标关怀模式放大到 26vp，
   低对比文字在关怀模式改用 `Theme.strong`；开关值存 Preferences。

## 语音播报与一键拨号（2026-10-27 升级）

### 做了什么
1. **全局语音播报（TTS）**：新增 `ets/utils/TtsManager.ets`，用 `@kit.CoreSpeechKit`
   （`@hms.ai.textToSpeech`）的 `createEngine` 创建离线中文引擎（person=13）。
   在 `EntryAbility.onCreate` 初始化、`onDestroy` 释放，属于**应用级单例**，
   首页/告警列表/详情页都能用。
2. **打开告警就念**：点开一条**未关闭**的告警详情时（`AlarmTab.openDetail`），
   按等级拼一句话念出来，已关闭的历史告警不再打扰：
   - L3（紧急，打断当前播报）：`警告，监测到紧急求助，请立即处理`
   - L1/L2（普通，排队等前一句念完）：`提醒，监测到卫生间长时间无活动，请及时确认`
   语速 0.9、音量 1.0（老人听不清等于没念）。
   > 为什么不做"列表轮询自动播"：APP 每 3 秒拉一次列表，自动播会让同一告警反复念、
   > 多条同时到达时互相叠加；改为"点开才念"，家属的注意力只落在真正要看的那一条上。
3. **一键拨号**：新增 `ets/utils/CallUtils.ets`，用 `common.UIAbilityContext.startAbility`
   发 `ohos.want.action.dial` + `tel:<号码>` 隐式 want，拉起系统拨号盘（只预填号码，
   最终是否拨出由用户点确认，符合"不替用户决策"的隐私习惯）。
4. **入口**：告警详情页在"建议措施"下新增红色「一键呼叫家属」按钮；号码优先级为
   「我的-个性化设置-家属电话」→ 缺省 `13800138000`，号码清洗只留数字、允许前导 `+`。

### 异常与退让（赛题四"关怀"视角）
- TTS 引擎创建失败：`ttsReady=false`，`speak` 直接返回 false，界面弹 toast
  「语音播报不可用，请留意屏幕提示」，**不阻塞告警流程**。
- 播报失败：停掉上一句再重试一次，仍失败只记日志，不弹窗打断家属处置。
- 拨号失败（无拨号应用 / 无权限 / 号码非法）：捕获 `BusinessError`，
  提示「这台设备不支持拨号，请手动拨打 158xxxx」，同时写 hilog。
- 号码非法（如空串）：不发 want，直接提示手动拨打。
