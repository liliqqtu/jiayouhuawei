## 三、实验步骤与实测结果

> **命令约定（Win10/11 自带 PowerShell 5.1 必读）**
> PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，不支持 `-X/-H/-d`，会报
> "找不到与参数名称 X 匹配的参数"。本文命令一律写成 **`curl.exe`**；若你的终端里
> `curl` 已是真 curl（PowerShell 7 或 Git Bash），去掉 `.exe` 一样能跑。
> **带 JSON 的 POST 在 PowerShell 里更难写**（引号会被拆掉，服务端收到 `BAD_JSON`），
> 所以本文的 POST 一律用 `python scripts/api.py ...`：它跑在 Python 里，不经过 PowerShell
> 的引号解析，`--kv key=value` 参数不需要写双引号。想用 curl 也行：把 JSON 存成文件再
> `curl.exe -d "@frame.json"`。
> 只想快点看结果的话，`python scripts/lab_demo.py` 能把 STEP 1–10 一次跑完并打印证据。

### STEP 1　网关自检

```powershell
curl.exe http://127.0.0.1:8780/health
```

**实测**

```
GET /health -> 200 {'ok': True, 'uptime': 2, 'version': '1.0.0'}
```

✅ 判定：`ok=true` 即网关存活。对应验收 **T01**。

---

### STEP 2　手工上报一帧（等价于开发板一次心跳）

```json
POST /api/v1/snapshot
{
  "deviceId": "lab-001",
  "ts": "2026-10-26T19:31:29+08:00",
  "seq": 1,
  "pirDetected": true,
  "lastMotionTs": "2026-10-26T19:31:29+08:00",
  "lastMotionZone": "living",
  "temperature": 23.4,
  "humidity": 51.0,
  "lux": 120.0,
  "doorOpen": false,
  "battery": null,
  "powerState": "mains",
  "source": "hardware",
  "fwVersion": "lab-0.1"
}
```

**实测返回**

```json
{"ok": true, "seq": 1, "channel": "http", "source": "hardware",
 "timeAdjusted": false, "alarms": []}
```

✅ 判定：`ok=true` 且 `source=hardware`。注意 `battery:null` 是**正确写法**（无电池不填 0）。

---

### STEP 3　查看 APP 首页会拿到什么

```powershell
curl.exe http://127.0.0.1:8780/api/v1/snapshot
curl.exe http://127.0.0.1:8780/api/v1/device
```

**实测**

| 字段 | 值 |
|---|---|
| deviceId | lab-001 |
| pirDetected | True |
| temperature | 23.4 |
| humidity | 51.0 |
| lux | 120.0 |
| doorOpen | False |
| source | hardware |
| online | True |
| staleSeconds | 0 |

`device -> online=True powerState=mains`

✅ 判定：`staleSeconds=0` 表示数据新鲜；若 >10 秒会变 `online=false`，APP 显示“数据已过期”。

---

### STEP 4　触发 L3：夜间卫生间长时间无活动

原理：先上报"02:10 卫生间有活动"，再上报"02:13 无活动"，间隔 3 分钟 > 夜间卫生间阈值 2 分钟。

**实测**

```
两帧上报后 -> 200 {'ok': True, 'seq': 3, 'alarms': ['EVT-20261026-0001']}
```

✅ 判定：`alarms` 非空即告警已生成。对应 **T03**。

---

### STEP 5　查看告警列表

```powershell
curl.exe "http://127.0.0.1:8780/api/v1/alarms?status=pending"
```

**实测**

```
EVT-20261026-0001  L3  pending  夜间卫生间连续 3 分钟未检测到活动
```

✅ 判定：等级 **L3**、状态 **pending**、文案只描述"未检测到活动"，**不含医学结论**。

---

### STEP 6　事件闭环：确认 → 处置 → 关闭

```powershell
# 确认（operator 可写家属称呼）
python scripts/api.py post /api/v1/alarms/EVT-20261026-0001/ack --kv operator=daughter

# 处置并关闭（handleType: visited / called / false_alarm / community）
python scripts/api.py post /api/v1/alarms/EVT-20261026-0001/close --kv handleType=visited --kv handleResult=已上门查看，老人安好
```

**实测**

```
ack   -> 200 status= acknowledged ackTs= 2026-10-26T19:31:30+08:00
close -> 200 status= closed        handleType= visited
```

✅ 判定：状态按 `pending → acknowledged → closed` 迁移，两个时间戳都留痕。对应 **T06**。

---

### STEP 7　状态机校验：重复关闭应被拒绝

**实测**

```
close again -> 409 {'code': 'INVALID_STATE', 'message': '告警已关闭，不允许重复关闭'}
```

✅ 判定：返回 **409** 而不是 200 —— 说明状态机真的在拦，不是摆设。

---

### STEP 8　日报数据

```powershell
curl.exe "http://127.0.0.1:8780/api/v1/reports/daily?date=2026-10-26"
```

**实测**

```
totalCount=2  alarmCount=1  level=normal
hourly(前8小时) = [0, 0, 1, 0, 0, 0, 0, 0]
```

✅ 判定：`hourly[2]=1` —— 凌晨 2 点那次活动被正确归档到 2 点这一格。

### STEP 9　切换到 Wi-Fi UDP 通道

不经过 HTTP，直接往网关 UDP 9998 打一帧 JSON。

**实测**

```
UDP 一帧后最新快照: deviceId=lab-udp source=test seq=4
```

✅ 判定：`source=test` 是被**故意**标成测试数据的——APP 上会显示“测试/模拟”角标。这条验证了：
1. UDP 通道可用；
2. 来源标注没有被"洗白"。

### STEP 10　非法报文不应导致崩溃

```powershell
python scripts/api.py post /api/v1/snapshot --kv deviceId=bad    # 缺 ts，应 400
UDP 发送 "{this is not json"
```

**实测**

```
缺字段 -> 400 {'code': 'BAD_REQUEST', 'message': '缺少必填字段：ts'}
发完非法包后 /health -> 200 True
```

✅ 判定：非法数据被拒且**服务仍存活**。对应 **T07** 的健壮性部分。

---

### STEP 11　月报与“已过天数”

前面 `device_sim` 跑了几分钟，活动会落到当天。看月报：

```powershell
curl.exe "http://127.0.0.1:8780/api/v1/reports/monthly?month=2026-10"
```

预期：`days` 是当月总天数（10 月为 31），`daysUsed` 是**已经过去的天数**（10/27 看就是 27，
历史月份等于整月），`dailyAvg = totalCount / daysUsed`。

为什么要分两个字段：10 月 27 号看 10 月，若按 31 天摊，日均会凭空低 13%，演示时会被问住。

### STEP 12　多设备：一台网关，两台设备

真实场景是"父母各一台/客厅卧室各一台"。网关按 `deviceId` 分区存储，
同一个 `seq` 不会互相覆盖，看板上也会出现设备下拉。

```powershell
# 1) 再上报一台老人设备（elder-002，没有活动）——api.py 不需要写任何双引号
python scripts/api.py push --device elder-002 --no-motion

# 2) 看设备清单（按最后上报倒序）
curl.exe http://127.0.0.1:8780/api/v1/devices

# 3) 分别看两台的最新快照——互不干扰
curl.exe "http://127.0.0.1:8780/api/v1/snapshot?deviceId=elder-001"
curl.exe "http://127.0.0.1:8780/api/v1/snapshot?deviceId=elder-002"

# 4) 查不存在的设备：应 404 NO_DATA（不能悄悄返回别人的数据）
curl.exe -i "http://127.0.0.1:8780/api/v1/snapshot?deviceId=elder-999"
```

浏览器打开 `http://127.0.0.1:8780/`，出现"这台网关带的设备"下拉，切换后
首页指标、待处理告警同步切换（只有一台设备时该下拉自动隐藏，不干扰演示）。

实测（临时网关 8781 + 两台设备，`scripts/_probe_step12.py` 跑出）：

```
1) 上报 elder-001 有活动 / elder-002 无活动
    200
    200
2) GET /api/v1/devices -> 200，count=2，设备: ['elder-002', 'elder-001']
3) 快照按设备隔离: elder-001.pirDetected=True / elder-002.pirDetected=False
4) 未知设备 -> 404（预期 404）
5) 看板可访问: / -> 200，含设备下拉: True
```

> 注意：`/api/v1/devices` 返回的是 `{"items": [...], "count": n}`，字段与
> `/api/v1/device` 完全一致——APP 的"我的"页与看板下拉共用这一个接口。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `curl` 连不上 | 网关没起 / 端口被占 | 换端口 `--port 8781`，或 `netstat -ano \| findstr 8780` |
| STEP 4 没生成告警 | 两帧间隔不够 | 确认第二帧 ts 比第一帧晚 ≥3 分钟 |
| UDP 那步没反应 | 忘了 `--udp-port 9998` | 重启网关带上该参数 |
| POST 报“找不到与参数名称 X” | 用了 PowerShell 别名 `curl`（= Invoke-WebRequest） | 改用 `curl.exe`，或直接用 `python scripts/api.py` |
| POST 返回 `BAD_JSON` | PowerShell 把内联 JSON 的引号拆掉了 | 用 `python scripts/api.py push/post`（见“命令约定”） |
| 中文乱码 | Windows 控制台编码 | `chcp 65001` 或设 `PYTHONIOENCODING=utf-8` |
| APP 连不上但电脑能 curl | 校园网客户端隔离 | 用手机热点，IP 变 192.168.x.x |
