## 2. `bench-01` 不是"未上报"，是早就报过数了

**为什么**：`bench-01` 是之前跑多设备验证脚本时真实上报过的设备，库里有它的历史快照，所以它显示"离线 · 电量 95% · 最后上报 10-27 21:44"，不是"未上报"。
"未上报"这个状态只会出现在**手动登记过、但从来没有过数据**的设备上（比如 `bench-07`/`bench-08`）。

**改了什么**：`scripts/clean_test_devices.py` 现在默认会把 `bench-*` 全删掉，让你有一个干净的起点：

```powershell

python scripts\clean_test_devices.py --all-extra    # 除 bearpi-001 外全删

```

**文档已改**：示例设备编号从 `bench-01` 换成 **`bench-09`**（一个肯定没出现过的号），这样"未上报 · 离线 · 电量—"一定是对的。

**验证**：「我的」→ 设备卡片输入框填 `bench-09` → `添加设备` → 出现 `bench-09 · 未上报 · 离线 · 电量—`，共 N 台 +1。

## 3. "告警提醒（震动+提示音）"开和不开有什么区别

| | 关 | 开 |
|---|---|---|
| 触发条件 | — | APP **在前台**、`nAlarms` 大于上次已知条数（3 秒轮询发现新告警） |
| 表现 | 什么都不发生 | 震动 + 播放 `rawfile/alert.wav` 提示音，权限首次会弹 |
| 抑制 | — | 15 秒内不重复；退出后台不响（没做后台服务） |

实现：`entry/src/main/ets/service/Alerter.ets`（`AVPlayer` 播 rawfile + `vibrator` 震动），在 `pages/Index.ets` 里随 `pendingAlarms` 轮询调用。

**模拟器上的实操**：
1. 关掉开关 → B 窗注入 `python sim\incident.py --type sos` → APP 无振动无声音（只会看到告警列表 +1）；
2. 打开开关 → 再注入一次（先 `--type reset`）→ 震动（模拟器弱）+ 提示音；
3. 验证日志（A 窗）：`& $HDC shell hilog -x | Select-String "Alerter"`，能看到 `alert fired`。

> 注意：这是**前台提醒**，不是系统推送。退到后台、锁屏都不会响——这点在答辩时要说清楚（也是"无推送通道"的边界）。

```typescript
// 保存：只提交填了的项，其余不动
private async saveThresholds(): Promise<void> {
  const body: ThresholdBody = {};          // 显式 interface，避免 arkts-no-untyped-obj-literals
  const map: string[] = ['noMotionMin', 'nightBathroomMin', 'tempHigh', 'tempLow', 'humHigh', 'doorOpenMin'];
  for (let i = 0; i < map.length; i++) {
    const raw = this.editValue(map[i]);
    if (raw.length === 0) { continue; }
    const n = Number(raw);
    if (Number.isNaN(n) || n <= 0) {
      this.thresholdErr = true; this.thresholdHint = '请填大于 0 的数字，或留空沿用默认值'; return;
    }
    this.putNumber(body, map[i], n);
  }
  this.thresholdErr = false;
  const ok = await ApiClient.saveThreshold(this.gateway, body);
  if (ok) { this.thresholdHint = '已保存，新的阈值马上对新数据生效'; }
  else { this.thresholdErr = true; this.thresholdHint = '保存失败：网关没响应，先点上面的“保存并测试连接”'; }
}
```

### 4.2 APP 侧：`service/ApiClient.ets`

```typescript
// 保存个性化阈值：只发勾选过的键，空对象直接返回 true
static async saveThreshold(base: string, body: ThresholdBody): Promise<boolean> {
  const url = `${base}/api/v1/config/threshold`;
  try {
    const res = await http.createHttp().request(url, {
      method: http.RequestMethod.PUT,
      header: { 'Content-Type': 'application/json' },
      extraData: JSON.stringify(body),
      connectTimeout: 4000, readTimeout: 4000
    });
    return res.responseCode >= 200 && res.responseCode < 300;
  } catch (e) {
    console.error(`[ApiClient] saveThreshold failed: ${JSON.stringify(e)}`);
    return false;
  }
}
```

## 5. `demo.ps1 -Stop` 直接敲会报错

**为什么**：`demo.ps1 -Stop` 是 **PowerShell 脚本参数**，不是 exe，必须用 `powershell -File` 调起来。
**改了什么**：文档所有命令都写成完整形式；另外 `demo.ps1` 在端口冲突时会**自动给出**该敲的那一行（不用你猜）。

正确写法（A 窗）：

```powershell
cd D:\shadowlamp
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Stop
```

常见误写与结果：

| 误写 | 现象 |
|---|---|
| `demo.ps1 -Stop` | `'demo.ps1' 不是内部或外部命令` |
| `.\scripts\demo.ps1 -Stop` | 执行策略报错（`无法加载文件…未数字签名`） |
| `powershell scripts\demo.ps1 -Stop` | 参数被当成位置参数，`-Stop` 不生效 |

> 顺带修了一个真 bug：`demo.ps1` 里 `-Stop` 原先只按端口杀进程，遇到"端口被别的程序占"就杀不掉也不提示；现在会打印占用 PID 并给出两条出路（`-Stop` 强制清、或 `-Port 8790` 换端口）。

## 6. 场景注入的两个问题（都已修）

### 6.1 `--type night` 应用无响应

**根因**：`--type night` 只发 2 帧"过去时刻"的回放帧（02:10 有人、02:13 无人），网关按夜间卫生间 2 分钟阈值判 L3。但如果**当前设备在 APP 里选中的不是 `bearpi-001`**，或者网关刚重启（3 分钟预热期），就会"注入了但 APP 没动静"。
另外旧脚本注入完只打印"去 APP 看"，没有告诉你去看哪一条——现在会直接打印**期望的告警类型/等级/文案**。

**改了什么**：
- `sim/incident.py` 每条场景注入后都打印 `期望：L3 紧急 · 夜间卫生间连续 N 分钟未检测到活动`；
- 注入前自动 `--type reset` 清掉上一场景的保持状态（避免门开/白天残留污染下一场景）；
- 判定口径确认：**夜间 + 卫生间 + 连续无活动 = L3**（正是你说的"疑似摔倒"场景），夜间其它房间 = L2，白天任意房间 = L2。

**验证**（A 窗确认网关在线、B 窗注入）：

```powershell
python sim\incident.py --type night
# 期望输出：期望：L3 紧急 · 夜间卫生间连续 2 分钟未检测到活动
# 3 秒内：APP 顶部变红「紧急告警」、告警页出现 L3 卡、电脑端警笛循环
```

### 6.2 缺少"白天人体长时间无活动"场景

**已新增 `--type idle`**（白天客厅连续 10 分钟无活动 → L2 关注，"疑似晕倒"）：

```powershell
python sim\incident.py --type idle
```

判定口径（与 `--type night` 的区别，答辩时可以用这张表）：

| 场景 | 时段 | 区域 | 阈值 | 等级 | 含义 |
|---|---|---|---|---|---|
| `--type idle` | 白天 | 任意 | `no_motion_min`=5 | L2 | 白天长时间不动，疑似晕倒 |
| `--type night` | 夜间 22:00–06:00 | **卫生间** | `night_bathroom_min`=2 | **L3** | 起夜时长时间无动静，最危险 |
| 夜间其它房间 | 夜间 | 卧室/客厅 | `night_no_motion_min`=3 | L2 | 夜里久未翻身/走动 |
| 睡眠时段 23:00–07:00 | 夜间 | 非卫生间 | `sleep_gap_min`=360 | L2 | 睡着不动是正常的，只有 6 小时才提醒 |

### 6.3 `--type door` 首页仍显示"门磁已关"

**根因**（这是个真 bug，不是文档问题）：模拟设备在**非保持模式**下每 2 秒都会重发一帧 `doorOpen=false`，把刚注入的"门开着"覆盖掉了；APP 每 2 秒拉最新帧，于是又显示"已关"。
**改了什么**：
- `sim/device_sim.py` 的保持机制（`data/.demo_hold`）现在带 `expires_at`，注入后**持续 12 分钟**按注入值上报，不会再被常规帧冲掉；
- 顺手修了网关一个语义 bug：**"关门那一帧如果 PIR 同时在动"= 回家**，不再误判成"外出"（`gateway/rules.py` 门磁状态机）。

**验证**：注入 `--type door` → 首页 `门磁` 变 **已开**、顶部变黄「有环境提醒 · 门窗已持续开启 12 分钟」；12 分钟后自动恢复，或 `--type reset` 立刻恢复。

### 6.4 另外一个容易踩的：网关刚启动时的"预热期"

网关启动后 **180 秒**内不判"时间累积型"告警（无活动/外出/门未关），防止一启动就拿历史时间戳报假警。
所以：**要么先起网关等 3 分钟再演示**，要么把这类场景放到流程后半段。瞬时类场景（SOS、温度、湿度、光照）不受预热影响，随时可演示。

## 7. "一键呼叫家属"在模拟器报"暂无可用打开方式"

**为什么**：模拟器镜像里**没有电话/拨号应用**，`startAbility(ACTION_DIAL)` 返回 `16000019 No matching ability is found`，系统弹的就是那句"暂无可用打开方式"。真机（有拨号盘）会直接跳到拨号界面并带出号码。

**改了什么**（`ets/utils/CallUtils.ets`）：拨号失败时**降级为"把家属号码复制到剪贴板 + Toast 提示"**，不再是干巴巴的系统报错：

```typescript
// 拨号失败（模拟器/平板无电话应用）→ 复制号码，让家属自己粘贴
const msg = code === '16000019'
  ? `这台设备没有拨号应用（模拟器/平板），家属号码已复制：${number}`
  : `拨号失败，家属号码已复制：${number}`;
await pasteboard.getSystemPasteboard().setData(
  pasteboard.createData(pasteboard.MIMETYPE_TEXT_PLAIN, number));
this.toast(msg);
```

**演示时怎么说**（诚实版）："评审现场用模拟器，所以这里演示的是降级路径——号码已复制，方便家属用自己手机拨打；真机上会直接拉起拨号盘。"
**验证**：告警详情 → `一键呼叫家属` → Toast「家属号码已复制：13800138000」；`hilog` 里能看到 `[CallUtils] dial failed: code=16000019`。
