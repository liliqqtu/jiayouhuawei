# 模拟器验收步骤 v2（2026-10-28 重写版）

> 一版说清"在哪个窗口、敲什么、看到什么才算过"。全程 25–30 分钟；不碰真机、不碰固件。
> 这版取代 `模拟器验收步骤.md`（v1 已作废，仅留档）。

---

## 0. 三个窗口，先分清

| 代号 | 是什么 | 在里面干什么 |
|---|---|---|
| **A 服务窗** | PowerShell 窗口一 | 起/停网关与模拟设备、构建、清理、`hdc` 命令 |
| **B 注入窗** | PowerShell 窗口二 | 只敲 `python sim\incident.py --type xxx` |
| **C 模拟器** | HarmonyOS 模拟器里的 APP | 只点按，不敲命令 |

A、B 两个窗口都先执行一次：

```powershell
cd D:\shadowlamp
$HDC = "D:\HarmonySetup\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe"
```

> `D:\shadowlamp` 是指向 `software` 的联接，路径短且全英文——避免中文路径在 PowerShell 里的编码坑。
> 脚本一律 `powershell -ExecutionPolicy Bypass -File scripts\xxx.ps1`，不要直接敲 `scripts\xxx.ps1`。

## 1. 启动模拟器

**GUI**：DevEco Studio → Device Manager → Local Emulator → `Mate 90 Pro` → Start（首次同意协议，冷启 30–60 秒）。

**命令行**（A 窗，省内存）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\emulator_ram.ps1     # 先看谁吃了内存
& $HDC list targets                                                    # 期望 127.0.0.1:5555
```

启动失败报 `00801005 内存不足 4.00GB`：关掉浏览器/微信/多余 DevEco 窗口后重试；不要调小 AVD 内存（与已存快照冲突）。

---

## 2. 起服务（A 窗）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 -Siren -Voice
```

**期望三行**：`监听 0.0.0.0:8780` / 网关地址 `http://10.202.43.46:8780` / `持续心跳模式（每 2.0s 一帧）`。验证：

```powershell
curl http://127.0.0.1:8780/health      # {"ok":true,...}
```

⚠️ **180 秒预热期**：网关刚启动的 3 分钟内不判"无活动/外出/门未关"这类**时间累积型**告警（防止重启拿历史时间戳误报）。
所以**先把瞬时类场景（SOS、温度、湿度、光照）演示完**，无活动/门磁放后面，或先起服务再讲架构。

## 5. 首页验收

| 看什么 | 怎么验 | 通过标准 |
|---|---|---|
| 实时刷新 | 停 4 秒 | 温度/湿度每 2 秒变 |
| 五项指标 | 人体活动/温度/湿度/光照/门磁 | 都有值；没接的显示 `—`（不造数） |
| 数据来源 | 底部小字 | `测试/模拟` + 黄色免责提示 |
| 过期提示 | 杀掉 device_sim 进程 | 10 秒后顶部"设备离线 · 数据已过期" |
| 一键求助 | **长按**橙色按钮 1.2 秒 | Toast「已发出求助」+ 电脑端警笛语音 + 告警页 +1 |

---

## 6. 告警页验收

1. 三个状态：待确认 / 处理中 / 已关闭 —— 列表随之变化，空态"暂无告警"；
2. `全部设备` ↔ `仅 xxx`：卡片显示所属 `deviceId`；
3. 点开待确认：**证据链**（触发时读数）+ **处置时间线** + **建议措施**；
4. 不填处置结果点 `确认告警` → 红字"请填写处置结果"；
5. 填"已上门查看，老人安好" → 选 chip → `确认告警` → 状态"处理中"；
6. `提交处置并关闭` → 进"已关闭"，时间线补记录。

## 7. 场景注入矩阵（B 窗）

```powershell
cd D:\shadowlamp
```

| 命令 | 注入内容 | 期望 | 观察点 |
|---|---|---|---|
| `python sim\incident.py --type temp` | 36℃ | L1 温度偏高 | 首页温度变红 + 黄条 |
| `python sim\incident.py --type hum` | 88% | L2 湿度偏高 | 湿度过高提示 |
| `python sim\incident.py --type lux` | 02:30 420lx | L1 夜间光照异常 | 光照值大 |
| `python sim\incident.py --type sos` | 随身求助 | **L3 紧急求助** | 顶部变红、电脑端连续警报 |
| `python sim\incident.py --type idle` | 白天客厅 10 分钟无活动 | L2 疑似晕倒 | 首页"人体活动 无活动" |
| `python sim\incident.py --type night` | 夜间卫生间无活动 | **L3 夜间卫生间** | 最危险组合（答辩重点） |
| `python sim\incident.py --type door` | 门磁 12 分钟未关 | L1 门窗持续开启 | 首页门磁 **已开**，持续 12 分钟 |
| `python sim\incident.py --type reset` | 清保持 + 关待确认 + 恢复心跳 | 一切归零 | 首页"一切正常" |

每条命令都会打印 `期望：Lx · 文案`，照着对 APP。注入后 3 秒内应有变化（APP 3 秒轮询）。

> 3 秒没动静：确认「我的」当前设备是 `bearpi-001`；确认网关在线（`curl /health`）；确认不在预热期。

## 10. 语音播报与一键呼叫

1. 打开任意告警详情 → 中文播报（「警告，监测到紧急求助，请立即处理」）；
   A 窗：`& $HDC shell hilog -x | Select-String TtsManager` → `speak ok`；
2. `一键呼叫家属`（号码来自「我的」→ 家属电话，默认 13800138000）：
   - **模拟器/真机**：都会打开系统**拨号盘**并预填号码（模拟器实测：打开拨号页，顶部显示 138 0013 8000，按绿色键即可拨出）；
   - 少数没有拨号应用的设备：弹窗显示号码 + 「再复制一次」，不会静默失败；
   - 日志：`[CallUtils] dial ok via strategy=1`（strategy=1 是 `viewData + tel:`，模拟器走这条）；
     若看到 `all strategies failed` 再看到 `number copied`，说明该设备确实没有拨号能力。

## 10.5 家属电话设置

1. 「我的」→ `家属电话` 卡片：输入框默认 13800138000；

## 15. 排错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `hdc list targets` 为空 | 模拟器没起 | Device Manager → Start，或 `emulator_ram.ps1` |
| APP 保存连接失败 | 地址写成局域网 IP | 模拟器场景必须 `http://127.0.0.1:8780` |
| 首页指标全 `—` | 模拟设备没跑 | 看 A 窗每 2 秒是否刷新 |
| 注入了但没变化 | 当前设备不是 bearpi-001 / 网关离线 / 预热期 | 切设备、`curl /health`、等 3 分钟 |
| 告警页空但有告警 | 停在「仅 xxx」 | 点「全部设备」 |
| 长按求助没反应 | 用了单击 | 长按 1.2 秒 |
| 呼叫报"暂无可用打开方式" | 模拟器无电话应用 | 预期，已降级复制号码 |
| TTS 没声音 | 模拟器缺中文语音包 | `hilog` 搜 `TtsManager` |
| 保存阈值返回 400 | 传了 0/负数 | 分钟类必须 ≥1 |
| 端口 8780 被占 | 上次没停 | `demo.ps1 -Stop`，或 `-Port 8790` 并改 APP 地址 |
