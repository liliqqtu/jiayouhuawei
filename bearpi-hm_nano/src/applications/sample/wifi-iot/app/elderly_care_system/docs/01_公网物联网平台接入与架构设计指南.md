# 独居老人居家安全监测系统 —— 公网物联网平台 (MQTT) 接入与架构方案

## 一、 为什么必须从局域网升级到公网 MQTT？

### 1.1 现有局域网 (UDP 单播) 的三大硬伤
| 痛点 | 局域网方案现状 | 用户的灾难体验 |
| :--- | :--- | :--- |
| **IP 变动即失联** | 代码硬编码 `CFG_GATEWAY_IP "10.179.139.87"` | 只要路由器重启、换个 Wi-Fi 或连手机热点，IP 变成 `192.168.x.x`，系统彻底断网，必须连电脑重新编译烧录 |
| **手机 App 需手动配 IP** | 手机必须手动输入网关电脑的局域网 IP | 严重违背适老化设计原则，普通老人和子女根本不懂什么是 IP 地址和端口号 |
| **出门在外无法报警** | 手机必须和小熊派在同一个 Wi-Fi 下 | **致命缺陷**：子女出门上班用 4G/5G 移动流量，老人在家跌倒或发生燃气泄漏，手机完全收不到报警！ |

### 1.2 公网 MQTT 架构解决之道
```
┌────────────────────────────────────────────────────────────────────────┐
│                        公网物联网整体拓扑架构                          │
│                                                                        │
│   [小熊派开发板]                                                        │
│   (无视内网IP变动)                                                     │
│        │                                                               │
│        │ MQTT Publish (连接固定公网域名，上报遥测与告警)                 │
│        ▼                                                               │
│   ┌──────────────────────────────────────────────────────────────┐     │
│   │           公网 MQTT Broker (云端中枢 / 消息中继)              │     │
│   │           域名: broker.emqx.io:1883 (或华为云 IoTDA)         │     │
│   └──────────────────────────────┬───────────────────────────────┘     │
│                                  │                                     │
│                 ┌────────────────┴────────────────┐                    │
│                 │ MQTT Subscribe (订阅设备 Topic) │                    │
│                 ▼                                 ▼                    │
│       ┌──────────────────────┐          ┌──────────────────────┐       │
│       │   手机 App / 小程序  │          │    电脑端综合管理台   │       │
│       │ (全球任意 4G/5G/Wi-Fi)│          │ (社区网格员监控大屏) │       │
│       └──────────────────────┘          └──────────────────────┘       │
└────────────────────────────────────────────────────────────────────────┘
```
- **核心逻辑**：
  1. 开发板连接的是固定的**公网域名**（例如 `broker.emqx.io`），开发板自身被分配成什么内网 IP 完全不重要；
  2. 手机 App 只要输入**设备唯一编码（DeviceID，如 `ElderlyCare_888` 或扫描机身二维码）**；
  3. 手机无论在公司、在地铁上还是在国外，只要有网，老人一按 SOS，**100 毫秒内全球直达推送**！

## 二、 公网 MQTT 主题 (Topic) 与报文规范

为实现多端协同，推荐规范化的 Topic 命名空间：

### 2.1 主题命名设计
- **设备遥测上报 (Device ➔ Cloud)**：
  `elderly_care/{device_id}/telemetry`
  - 周期：每 1~3 秒上报一次环境状态。
- **设备紧急告警 (Device ➔ Cloud)**：
  `elderly_care/{device_id}/alarm`
  - 触发：发生 SOS、跌倒未活动、燃气泄漏、门长开时瞬间推送。
- **云端控制下发 (Cloud ➔ Device)**：
  `elderly_care/{device_id}/control`
  - 场景：子女手机远程消警、调节语音音量、远程请求即时测量。

### 2.2 告警报文 JSON 格式示例
```json
{
  "device_id": "ElderlyCare_888",
  "msg_type": "alarm",
  "timestamp": 1730902800,
  "alarm_type": "SOS",
  "sos_source": "wireless_remote",
  "alarm_level": "critical",
  "temp": 24.5,
  "humi": 58.2,
  "door_open": 0,
  "last_motion_sec": 12,
  "alert_text": "紧急求助触发，已通知家属与社区网格员"
}
```

## 三、 推荐接入方案对比与演进路线

### 方案 A：公共免费 MQTT Broker（开发测试、校内答辩极速落地 ⭐⭐⭐⭐⭐）
- **服务器地址**：`broker.emqx.io`（端口 `1883`）
- **优势**：
  - **免注册、免买云服务器、0 元成本**；
  - 任何人只要连上公网即可通，开发板通过 DNS 自动解析域名；
  - 电脑上下载开源软件 **MQTTX**，手机上下载 **MQTT Dashboard App** 或自写微信小程序，填上 `broker.emqx.io` 立即通联。

### 方案 B：华为云 IoTDA（项目正式商用、国家级竞赛首选 ⭐⭐⭐⭐⭐）
- **华为云接入点**：`iot-da.cn-north-4.myhuaweicloud.com:1883`
- **优势**：
  - 鸿蒙（OpenHarmony）生态亲儿子，官方提供完整三元组鉴权和设备影子（Device Shadow）；
  - 支持免代码对接华为云短信通知、电话告警与微信推送；
  - 提供每月 100 万条免费消息额度，完全足够长期免费运行。

## 四、 电脑端如何接收开发板的公网信号？

在电脑端，您可以采用以下两种极为方便的方式接收并可视化：

1. **方式 1：使用专业桌面调试工具 (MQTTX)**
   - 下载并安装 [MQTTX (跨平台开源 MQTT 客户端)](https://mqttx.app/zh)；
   - 新建连接：服务器填 `broker.emqx.io`，端口 `1883`；
   - 添加订阅主题：`elderly_care/+/alarm` 和 `elderly_care/+/telemetry`；
   - 只要小熊派发出信号，电脑界面会立刻像聊天软件一样一条条实时刷新。

2. **方式 2：Python 监控脚本（50 行代码打造全自动大屏）**
   - 电脑运行一个 Python 脚本（利用 `paho-mqtt` 库），接收到 SOS 信号时：
     - 在电脑屏幕中央直接弹出红色告警弹窗；
     - 电脑音响自动播放警报音；
     - 自动把告警日志追加写入本地 CSV 或数据库。
