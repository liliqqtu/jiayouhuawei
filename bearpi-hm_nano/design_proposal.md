# 独居老人居家安全监测与应急辅助系统 —— 设计方案

## 一、 项目背景与设计目标

### 1.1 项目背景
随着我国人口老龄化进程加速，高龄空巢、独居老人的比例持续攀升。独居老人由于身体机能衰退，极易在日常生活中发生突发性疾病、意外跌倒、夜间迷途走失或室内用电用火安全事故。然而，由于独居缺乏常态化照料，老人在遭遇突发意外时往往无法自主报警或及时呼救，造成“黄金抢救时间延误”，极易酿成严重人身安全后果。

传统基于穿戴式设备（如智能手环、跌倒手表）的监护方案，由于需要老人频繁充电、主动佩戴，极易因老人遗忘、排斥佩戴而造成监护“窗口期”失效；而传统的室内网络摄像头方案又存在严重的隐私侵犯隐患，在卫生间、卧室等高危跌倒场所难以部署。

### 1.2 设计目标
针对上述社会痛点，本项目基于开源鸿蒙（OpenHarmony）轻量系统与北向分布式应用架构，研发了一套**“非感官接触式、高隐私保护、端边端一体化协同”**的独居老人居家安全监测与应急辅助系统。系统旨在实现：
1. **多维度被动感知**：利用热释电红外人体感应、干簧管门窗磁传感器、微气候温湿度传感器，实现老人活动轨迹与出入状态的隐形守护，免除穿戴负担；
2. **抢占式主动呼救与本地声光联动**：提供随身便携式紧急 SOS 按键，结合现场蜂鸣器与爆闪 LED，在异常发生瞬间拉响现场警报，震慑风险并呼唤邻里关注；
3. **移动端实时互联与全景监护**：基于 OpenHarmony 纯血鸿蒙技术栈开发手机端 ArkTS 原生应用，子女与网格员通过手机端实时掌握家中温湿度、活动倒计时、门窗开关状态，实现远程移动监护；
4. **事件闭环管理工作台**：预警发生后，子女与社区网格员通过手机 APP 或 Web 工作台一键确认、排查、反馈处置结论，形成电子化居家安全日志台账，实现安全隐患全周期闭环追踪；
5. **智能健康生活规律图谱**：自动统计分析 24 小时活跃时段分布及 7 日活动趋势，辅助子女及早研判老人身体衰退征兆。

## 二、 系统总体技术架构

系统整体遵循 OpenHarmony “软硬协同、南北结合、统一互联”的技术架构原则，分为**南向设备感知层**、**边缘网关与通信层**以及**北向移动应用与管理层**三层架构体系。

```
┌─────────────────────────────────────────────────────────────┐
│             北向应用与移动端 (OpenHarmony ArkTS)             │
│  ┌───────────────────────┐  ┌────────────────────────────┐  │
│  │ 华为手机原生应用 (APP)  │  │ 边缘 Web 全景看板 (PC/平板) │  │
│  │ • 实时仪表盘 / 状态指示│  │ • 事件闭环处置电子台账     │  │
│  │ • 紧急告警红闪推送与消警│  │ • 24h时段分布与健康规律图谱│  │
│  └───────────────────────┘  └────────────────────────────┘  │
└──────────────────────────────▲──────────────────────────────┘
                               │ RESTful API / WebSocket / JSON
┌──────────────────────────────┴──────────────────────────────┐
│                    边缘网关与通信层 (Gateway)                 │
│   • 局域网高速 HTTP/UDP 接入 (端口 8780 / 9999)              │
│   • 硬件串口降级穿透桥接 (COM / USB-Serial 直收)            │
│   • 告警判定引擎、SQLite 状态持久化与断网补传去重机制        │
└──────────────────────────────▲──────────────────────────────┘
                               │ POST /api/v1/snapshot
┌──────────────────────────────┴──────────────────────────────┐
│             南向设备感知控制层 (BearPi-HM Nano / Hi3861)     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐   │
│  │ E53_IS1 红外 │  │ 干簧管门窗磁  │  │ 室内温湿度微气候 │   │
│  │ (GPIO_7 中断)│  │ (GPIO_13 上拉)│  │ (环境舒适与火险) │   │
│  └──────────────┘  └──────────────┘  └──────────────────┘   │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐   │
│  │  板载 F1 按键 │  │  板载 F2 按键 │  │ 本地高分贝声光   │   │
│  │ (紧急 SOS 求助)│ │ (消警复位按键)│  │ (PWM1 蜂鸣+LED) │   │
│  └──────────────┘  └──────────────┘  └──────────────────┘   │
│  ┌──────────────────────────────────────────────────────┐   │
│  │          CMSIS-RTOS v2 多任务调度与异常判定状态机       │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

1. **南向设备感知控制层**：运行 OpenHarmony LiteOS-M 内核，主控采用海思 Hi3861V100 RISC-V 芯片，多任务实时调度红外人体感应、干簧管门窗磁开关、SOS 求助键与室内微气候检测，通过本地状态机实现毫秒级声光告警与自主消警仲裁。
2. **边缘网关与通信层**：采用轻量级、高容错的数据中枢架构，支持 Wi-Fi 网络（HTTP POST/UDP）与 USB 串口桥接双轨并行接入，提供 SQLite 事务存储、断网补传、设备在线监测与分级告警状态机（L1/L2/L3）。
3. **北向移动应用与管理层**：包含华为手机鸿蒙原生应用（基于 ArkTS / API 12 开发）与响应式 Web 控制中心，提供全景监护、弹窗告警、工单处置与生活作息大数据图谱。

## 三、 硬件选型与引脚电气设计

### 3.1 核心硬件选型
- **核心主控开发板**：小熊派 BearPi-HM Nano。搭载海思 Hi3861V100 高度集成 2.4GHz Wi-Fi SoC 芯片，集成 32 位 RISC-V 微控制器，最大主频 160MHz，内置 352KB SRAM 与 288KB ROM，支持硬件浮点与安全引擎，专为物联网与 OpenHarmony 轻量设备开发设计。
- **人体活动感应扩展板**：BearPi E53_IS1。集成数字热释电红外传感器与高分贝无源蜂鸣器，有效感应角度达 100°，感应距离达 3~5 米，检测到有人走动时输出高电平脉冲。
- **门窗磁传感器**：高灵敏度磁敏干簧管组件。采用磁性接近吸合原理，门窗关闭时磁铁吸合触点导通接地；门窗打开时触点断开，利用芯片内部上拉输出高电平，具有无机械磨损、零待机功耗、高可靠等特性。
- **环境温湿度传感器**：E53_IA1 板载工业级 SHT30 I²C 传感器（集成微气候动态平滑补偿算法），测温精度达 ±0.2℃，测湿精度达 ±2%RH。
- **紧急求助输入**：板载微动轻触按键 F1 与消警按键 F2，自带硬件抗冲击设计。

### 3.2 硬件引脚分配与防冲突设计
针对 E53 接口标准与扩展座硬件布局，经过精细排查与电气核算，彻底解决了 GPIO 复用冲突，最终硬件管脚分配如下：

| 功能模块 | 对应外设 / 器件 | 硬件 GPIO 映射 | J1 扩展座管脚 | 信号方向与配置属性 |
| :--- | :--- | :--- | :--- | :--- |
| **人体活动感应** | E53_IS1 热释电红外 | `GPIO_7` | J1 第 7 脚 | 数字输入，内部上拉，上升沿硬件中断 |
| **本地报警蜂鸣** | E53_IS1 无源蜂鸣器 | `GPIO_8` | J1 第 8 脚 | PWM 输出，复用为 `PWM1`（4kHz / 50% 占空比） |
| **门窗磁检测** | 干簧管传感器组件 | `GPIO_13` | J1 第 5 脚 | 数字输入，开内部上拉（闭合=0，断开=1） |
| **紧急求助按键** | 板载 F1 按键 (SOS) | `GPIO_11` | J1 第 15 脚 | 数字输入，开内部上拉，按下接地（低电平有效） |
| **现场消警复位** | 板载 F2 按键 (RESET)| `GPIO_12` | J1 第 2 脚 | 数字输入，开内部上拉，按下接地（低电平有效） |
| **系统运行/警报**| 板载黄色高亮 LED | `GPIO_2` | J1 第 6 脚 | 数字输出，正常慢闪（心跳），告警急促爆闪 |
| **调试与遥测串口**| CH340 板载串口芯片 | `GPIO_3` / `GPIO_4` | J1 第 20/17 脚 | UART0，波特率 115200 8N1，输出标准 JSON 遥测流 |

## 四、 软件架构与网络协同机制

### 4.1 数据交互契约与标准化协议
南向设备与网关之间采用标准化的 Snapshot 快照协议（`POST /api/v1/snapshot`），包含设备完整感知状态：
- `deviceId`：设备唯一标识（如 `bearpi-001`）；
- `pirDetected`：布尔值，是否检测到人体活动；
- `lastMotionTs`：最后一次检测到移动的 ISO 时间戳；
- `temperature` / `humidity`：室内实时温度与相对湿度；
- `doorOpen`：布尔值，门窗磁开闭状态；
- `battery` / `powerState`：供电状态与电量信息。

### 4.2 手机原生鸿蒙应用（ShadowLamp）功能设计
手机端基于 DevEco Studio 与 OpenHarmony ArkTS 开发，深度适配 HarmonyOS 设计语言：
1. **首页监护大屏（HomeTab）**：展示家中温度、湿度、最后活动时间、门窗磁开关状态及健康评级；
2. **告警闭环工作台（AlarmTab）**：接收 L1（提示）、L2（关注）、L3（紧急）三级告警推送，监护人可一键确认、电话核实、填写处置结果完成事件闭环；
3. **健康规律报告（ReportTab）**：展示 24 小时活跃时段柱状图、7 日活动趋势与健康基线评分；
4. **多网络自适应（MineTab）**：用户可在设置中自由切换局域网与远程网关地址，实现随心切换。

## 五、 事件闭环管理工作台与大数据规律分析

### 5.1 事件闭环管理业务流
赛题明确强调“事件闭环管理”要求。本系统设计了标准的闭环台账引擎：
```
[传感器异常触发] ──► [本地声光报警 + 网关/手机APP推送]
                             │
                             ▼
                   [手机端弹出预警处置窗口]
                             │
                             ▼
                 [子女/网格员上门核实与电话排查]
                             │
                             ▼
              [录入处置结论 (老人平安/送医/误报)]
                             │
                             ▼
                   [生成安全电子台账并消警归档]
```
处置结论支持一键导出为标准 CSV/电子表格台账，支持长期跟踪老人健康与生活状态。

### 5.2 老人生活健康与活动规律可视化
系统根据全天候感知数据，构建了老人日常生活行为画像：
1. **24 小时活跃时段分布柱状图**：清晰描摹老人的起夜频率、晨起时间、做饭时段与就寝作息；
2. **7 日活动趋势与健康评分模型**：实时比对今日总活动量与历史均值。如系统测算得出“今日活动频次较昨日下降 22%”，系统自动标黄并提示监护人重点问候，及早预防潜在慢性疾病恶化。

## 七、 创新亮点与竞赛竞争力总结

1. **端边端全链路一体化**：从海思 Hi3861 嵌入式内核到边缘网关，再到华为手机原生 ArkTS 鸿蒙应用，全栈采用国产自主可控技术体系；
2. **无感守护与绝对隐私保障**：全系统无需老人佩戴任何电子元件，杜绝漏充漏戴；不采集任何音视频隐私，全天候无感守护；
3. **真实可用的事件闭环机制**：突破了传统物联网“只报不管”的弊端，深度契合社区基层网格治理与家庭适老监护实战需求，形成了“预警-排查-处置-归档”的完整业务台账闭环；
4. **双轨高可靠网络传输**：支持 Wi-Fi STA 网络无线透传与 USB 串口桥接双模热备，彻底杜绝比赛路演现场因网络环境复杂造成的断联风险。
