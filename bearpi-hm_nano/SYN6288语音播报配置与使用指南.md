# SYN6288 智能语音合成播报模块配置与使用指南

本指南详细说明了在“独居老人居家安全监测与应急辅助系统”项目中，如何配置、修改和调试 **SYN6288 中文 TTS 语音播报模块**，并详细解析了各类预置告警语音的设计。

---

## 一、 开机不发音/播报失败的核心原因剖析

在之前的调试中，若发现烧录后开机没有出声，根本原因包含以下三点：

1. **帧数据长度定义偏差（核心协议错误）**：
   * 官方芯片手册规定，帧头 `0xFD` 之后的高低两字节长度是指**整段数据区（含命令字、命令参数、文本内容、异或校验和）的总字节数**，即 `总长度 = 文本字节数 + 3`。
   * 此前底层驱动中写成了 `+ 2`，少算了 1 字节校验和长度。SYN6288 芯片检测到数据长度不符，会直接丢弃该数据包。
2. **源码字符集编码冲突（静音根源）**：
   * DevEco-Studio / VS Code 保存的源文件默认为 `UTF-8` 编码（每个汉字 3 字节）；
   * 而协议头若声明为 `0x01`（GBK 编码，每个汉字 2 字节），SYN6288 试图将 UTF-8 字节当做 GBK 解码时会产生大量非法码字。
   * **芯片手册特别强调**：“*对于在此编码范围之外的不可识别文本，芯片将静音不播放*”。
3. **引脚复用被后续 GPIO 方向设置覆盖**：
   * 在调用 `IoTGpioSetFunc` 复用为 `UART1_TXD` 之后，若额外调用 `IoTGpioSetDir`，有时会将引脚强行切回普通的 GPIO 输出模式，导致串口信号无法正常送达模块。

> [!NOTE]
> **已实施的彻底解决方案**：
> 1. 新增 `VoicePlayPresetAlert()` 专属告警函数，所有系统预置告警词直接采用**预编译的纯正 GBK 二进制协议帧**，避开编译器与编码转换，100% 保障出声；
> 2. `VoicePlayText()` 通用文本接口内嵌了高精度 `UTF-8` 转 `UTF-16BE (Unicode 格式 0x03)` 转换引擎，严格匹配数据长度与 ECC，支持任意动态文字播报；
> 3. 清理了 `IoTGpioSetDir` 冗余代码，并在开机初始化后保留 500ms 芯片就绪延时。

## 二、 硬件接线与供电说明

| SYN6288 模块引脚 | 对应小熊派排母 / 面包板 | 引脚功能与复用说明 | 注意事项 |
| :--- | :--- | :--- | :--- |
| **VCC** | **面包板 5V 供电轨**（源自小熊派 J1 第 20 孔） | 模块主电源（5V） | **严禁接 3.3V！** 功放需要 5V 驱动，若接 3.3V 会导致声音极小、破音或掉电重启 |
| **GND** | **面包板公共负极轨**（共地连接到 J1 第 17/19 孔） | 电源地与参考地 | **两个面包板必须共地**，否则串口电平无法识别 |
| **RXD** | **J1 右列第 13 孔**（丝印 `UART_TX`） | 对应主控 **`GPIO_6`**（`UART1_TXD`） | **交叉连接**：模块的 RXD 接开发板的 TXD |
| **TXD / BUSY** | **J1 右列第 12 孔**（丝印 `UART_RX`） | 对应主控 **`GPIO_5`**（`UART1_RXD`） | 用于接收芯片回传状态或检测忙信号 |
| **SPK+ / SPK-** | 外接扬声器小喇叭 | 8Ω 0.5W ~ 2W 小喇叭 | 无正负极之分，直接焊接或插接 |

## 三、 各类报警专属语音设置清单

系统为主控状态机中的每一种安全事件，都定制了**具备适老化特征的专属发音参数**（包含专属提示音、自适应警报音量、放慢语速）：

| 告警场景 / 枚举标识 | 播报内容与控制标签 | 适老化特征设计 |
| :--- | :--- | :--- |
| **开机自检就绪**<br>`VOICE_ALERT_BOOT` | `[sound101]系统启动，守夜人守护已就绪` | 清脆“叮咚”开机音，舒缓平稳，确认设备完好 |
| **紧急求助 (SOS)**<br>`VOICE_ALERT_SOS` | `[sound105][v16][s4]紧急求助触发，已通知家属与社区网格员` | 最高级警报音效、最大音量 16、适中语速，给老人即时心理定心丸 |
| **紧急求助持续复播**<br>`VOICE_ALERT_SOS_REPEAT` | `[sound102][v16][s4]紧急呼救中，已通知家属与网格员` | 警示蜂鸣音，每 25 秒温和复播一次，避免老人恐慌 |
| **疑似跌倒 (长时间未活动)**<br>`VOICE_ALERT_NO_MOTION` | `[sound102][v15][s3]长时间未检测到活动，请确认老人安全` | 警示音、大音量 15、**放慢语速 `[s3]`**，让可能倒地的老人听清 |
| **入户门长开未关**<br>`VOICE_ALERT_DOOR_TIMEOUT` | `[sound101][v13][s4]门窗长开未关，请及时确认` | 提示音、适中音量 13，提醒随手关好防盗门 |
| **室内温度过高**<br>`VOICE_ALERT_TEMP_HIGH` | `[sound103][v15][s4]室内温度过高，请注意防火` | 火警提示音、高音量 15，防范厨房干烧与夏季中暑 |
| **室内温度过低**<br>`VOICE_ALERT_TEMP_LOW` | `[sound101][v12][s3]室内温度过低，请注意保暖` | 温和提示音、慢语速 `[s3]`，关怀防寒 |
| **浓烟与燃气火险**<br>`VOICE_ALERT_SMOKE` | `[sound105][v16][s4]检测到浓烟或燃气泄漏，请立即开窗并撤离` | 强警报音效、满格音量 16，避险指导指令明确 |
| **现场消警复位**<br>`VOICE_ALERT_CLEAR` | `[sound101][v12][s4]告警解除，系统恢复正常守护` | 舒缓叮咚音，告知老人险情已排除，恢复平静 |
| **音量调节反馈**<br>`VOICE_ALERT_VOL_TEST` | `[sound101]音量已调节` | 收到局域网/手机 UDP 调音指令时的即时听觉确认 |

## 四、 如何在代码中调用与修改

### 1. 触发预置告警语音（推荐方式）

在 [`elderly_care_main.c`](file:///D:/Dream/bearpi-hm_nano/src/applications/sample/wifi-iot/app/elderly_care_system/elderly_care_main.c) 中直接调用：

```c
#include "voice_syn6288.h"

// 触发开机语音
VoicePlayPresetAlert(VOICE_ALERT_BOOT);

// 触发 SOS 报警语音
VoicePlayPresetAlert(VOICE_ALERT_SOS);

// 触发消警语音
VoicePlayPresetAlert(VOICE_ALERT_CLEAR);
```

### 2. 动态文本播报与数值拼接

若需要动态朗读传感器读数（如温湿度数值），驱动底层会自动处理为 Unicode 发送：

```c
char msg[128];
snprintf(msg, sizeof(msg), "[s4]当前室内温度为%.1f度，环境正常", g_care_data.temperature);
VoicePlayText(msg);
```

## 五、 局域网手机/上位机无线远程调音

系统内置了 UDP 网络指令监听服务（运行于端口 `9998`），支持通过局域网无线控制音量：

* **控制端口**：`UDP 9998`
* **发送 JSON 指令**：
  ```json
  {"cmd":"setVolume","volume":15}
  ```
* **硬件响应**：
  1. 开发板自动调整音量寄存器至 15；
  2. 开发板回传确认响应给上位机：`{"status":"ok","volume":15}`；
  3. 扬声器自动播报：“*叮咚，音量已调节*”。
